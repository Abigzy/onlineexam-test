## 二、过程中出现的异常与处理

### 1）首次跑通即 404：种子数据缺班级关系

现象：`GET /api/v1/exams/` 返回 `count=0`，`POST /api/v1/exams/1/start/` 返回 `{"code":40400}`。

原因：`Exam.open_to_all_scope()` 对**教师创建**的考试，只覆盖「该教师可管理班级里的学生」。
被测项目的 `perf_seed.py` 建了 130 个学生却没有建班级，学生因此不在参考范围内。

处理：在 `scripts/seed.py` 里补建「压测教学班」并 `students.set(...)`，被测项目一行未改。

### 2）Locust 请求全部走系统代理

现象：`urllib`/`curl` 访问 `127.0.0.1:8024` 返回 502。

原因：本机设置了 `HTTP_PROXY/HTTPS_PROXY`，requests 会把回环地址也交给代理。

处理：`scripts/run_case.py` 启动 Locust 子进程时剔除所有 `*_proxy` 变量并设 `no_proxy=127.0.0.1,localhost`。

### 3）交卷脚本把真实失败伪装成脚本异常

现象：开考 404 时日志里是 `HTTPError(...)`，看不到自己写的「开考失败：404」。

原因：`resp.failure()` 只能在 `catch_response=True` 的上下文里调用，原脚本开考分支漏了这个参数，
调用时抛 `AttributeError`，真实原因被覆盖。

处理：压测副本给开考请求加了 `catch_response=True`。

### 4）判分场景 0 请求（第一次）

现象：`rs_grade10` 跑完 `req=0`，无异常记录。

原因：10 个教师用户全部卡在 `on_start` 的 `GET /grading/queue/` 里。该接口耗时随作答数线性增长
（当时累积 1629 份作答，单次 10-12 秒），90 秒内一条判分请求都发不出去。

处理：`scripts/make_grade_sample.py` 预置「一个班 50 份待批卷」并把 attempt id 冻结到
`scripts/.perf_grade_sample.json`，判分场景直接读名单。判分 P95 因此从 1600 ms 回到 340 ms（waitress 口径）。

### 5）100 并发在 runserver 下出现连接级失败

现象：`rs_step100` 79 次失败（7.25%），`rs_start50` 12 次（1.05%），错误都是 `status=0`。

原因：开发服务器在高并发瞬时建连时监听队列被打满，连接被拒/重置。同样负载换 waitress **0 失败**。

### 6）后台起服务被沙箱拦

现象：`bash.exe` 读不到自己的运行时文件、python 读不到 `pyvenv.cfg`。

处理：新增 `scripts/run_with_server.py`，把「起服务 → 跑用例 → 关服务」放进同一个前台进程，
顺带保证每轮口径干净、端口不串味。后续所有轮次都用它。

### 3.4 阶梯对照（交卷场景）

| 并发 | runserver RPS | runserver P95 | waitress RPS | waitress P95 | 连接复用 RPS | 连接复用 P95 |
|---|---|---|---|---|---|---|
| 10 | 12.49 | 690 | 12.95 | 620 | - | - |
| 20 | 11.99 | 2000 | 12.96 | 1500 | - | - |
| 50 | 12.15 | 5700 | 12.76 | 3800 | 45.22 | 840 |
| 100 | 12.31 | 9800 | 12.35 | 8200 | 42.11 | 2200 |

**读法**：前两组并发从 10 涨到 100，TPS 纹丝不动（12-13），延迟线性上涨——典型的「单队列排队」。
第三组换了连接策略后，同样 50 并发下 TPS ×3.5、P95 ÷4.5。

### 3.5 稳定性 soak（50 并发 15 分钟，连接复用）

| 指标 | 结果 |
|---|---|
| 总请求 | 35178，失败 0 |
| 平均 RPS | 39.14 |
| P50 / P95 / P99 | 410 / 710 / 920 ms |
| 前 7.5 分钟 P95 → 后 7.5 分钟 P95 | 717 → 695 ms（-3.0%） |
| 前 7.5 分钟 RPS → 后段 RPS | 39.4 → 38.5（-2.3%） |
| 进程 RSS | 108.8 → 110.1 MB（+1.2%） |
| 连接峰值 | 50（稳定，无堆积） |

结论：**没有内存泄漏，也没有随时间劣化**。RSS 涨 1.2% 属于 Python 分配器的高水位，不是泄漏形态
（泄漏会单调爬升且不回落）。
