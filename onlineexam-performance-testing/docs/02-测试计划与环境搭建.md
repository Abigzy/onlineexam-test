## 二、三组服务口径（用户确认：做对照）

| 口径 | 起法 | 说明 |
|---|---|---|
| `runserver` | `scripts/serve.py --server runserver` | Django 开发服务器（默认多线程），历史基线口径 |
| `waitress` | `scripts/serve.py --server waitress --threads 8` | 生产级 WSGI，8 线程；Windows 无 gunicorn |
| `waitress-conn60` | 上面再加 `--conn-max-age 60` | 调优组：开启数据库连接复用 |

三组共用同一份 `perf_settings.py`（`DEBUG=False`、窄 ALLOWED_HOSTS、无 DRF 调试渲染器、日志降级），
差别只在服务器类型与连接复用参数，保证可比。

## 三、环境变量与启动

> 所有命令在**核心工程** `D:\onlineexam-performance-testing\onlineexam_performance_testing` 下执行。

```bash
cd /d/onlineexam-performance-testing/onlineexam_performance_testing

# 0) 装依赖（复用被测项目 venv；版本组合见 requirements.txt）
D:/OnlineExam/.venv/Scripts/python.exe -m pip install -r requirements.txt

# 1) 准备数据（重建 130 个学生账号 + 1 份 20 题卷 + 1 场考试 + 1 个班级）
D:/OnlineExam/.venv/Scripts/python.exe scripts/seed.py --students 130

# 2) 起服务（推荐用 run_with_server.py 把起停包在一起；单起服务用 serve.py）
D:/OnlineExam/.venv/Scripts/python.exe -u scripts/serve.py --server waitress --threads 8
# 调优组再追加 --conn-max-age 60

# 3) 造「一个班 50 份待批卷」，同时冻结判分名单
D:/OnlineExam/.venv/Scripts/python.exe scripts/make_grade_sample.py --count 50
```

`scripts/seed.py` 在调用被测项目自带的 `perf_seed.py` 之后，额外补三件事（原因见该脚本头注释）：

1. 建「压测教学班」并把 130 个学生放进去——`open_to_all` 的教师考试只对该教师可管理班级的学生开放，
   没有班级关系时学生 `GET /exams/` 返回空、`POST /exams/{id}/start/` 404；
2. 把 `max_attempts` 抬到 1000、刷新考试时间窗，避免被业务规则（次数用完）和时间窗污染失败率；
3. 重新离线签发 access token——simplejwt 默认 60 分钟过期，隔一段时间再跑旧 token 全部 401。

## 四、账号与限流

- 132 个账号的 access token 由 `perf_seed.py` 用 `RefreshToken.for_user` **离线签发**，
  压测全程不发登录请求。原因：登录接口有 `auth` 限流 30/min（按 IP），
  所有虚拟用户都来自 127.0.0.1，逐用户登录会在第 30 次之后集体 429，失败率直接失真。
- 130 个学生 > 100 并发，保证每个虚拟用户独占一个账号，
  否则两个用户共用同一账号会抢同一个 attempt，产生假失败。

## 五、验收阈值（按「学生点一下到出结果」的可感知上限反推）

| 场景 | 并发 | 阈值 |
|---|---|---|
| A 并发交卷 `ExamSubmitUser` | 50（一个班） | 错误率 0，P95 < 1000 ms |
| B 开考读峰 `ExamStartBurstUser` | 50 | 错误率 < 0.5%，P95 < 1500 ms |
| C 教师判分 `ExamGradingUser` | 10 | 错误率 0，P95 < 800 ms |
| D 混合 `ALL` | 50 | 错误率 < 0.5%，P95 < 1500 ms |
| 稳定性 soak | 50，15 min | P95 前后段漂移 < 20%，RSS 无单调上涨 |

> 说明：Django/DRF 的 HTTP 开销在本机约 2-5 ms，因此阈值留出的余量足够大；
> 阈值是「能不能用」的线，不是「优不优美」的线。

## 七、执行方式（可中断、可续跑）

```bash
# 推荐：起服务 → 跑一轮 → 关服务（一条命令，端口不串味）
D:/OnlineExam/.venv/Scripts/python.exe scripts/run_with_server.py \
    --mode waitress --threads 8 --conn-max-age 60 --suite waitress-conn60 --resume

# 服务已在跑时，直接调 run_suite
D:/OnlineExam/.venv/Scripts/python.exe scripts/run_suite.py --server runserver --resume
D:/OnlineExam/.venv/Scripts/python.exe scripts/run_suite.py --server waitress --only step050,start50

# 看进度
D:/OnlineExam/.venv/Scripts/python.exe scripts/progress.py
```

每个用例是**独立进程**，结果单行追加到 `report/results.csv`，
因此中途中断最多丢一个用例，重跑时 `--resume` 自动跳过已完成项。

## 八、必守红线

1. 压测库名必须是 `online_exam_perf`，`serve.py` / `seed.py` 都会在库名不符时直接退出。
2. `AI_PROVIDER=mock` + 判分固定 `with_ai=false`，双保险防计费。
3. 只压 `127.0.0.1`，不对外网发压。
4. 压测期间服务端 `DEBUG=False`（`perf_settings.py` 强制），否则 SQL 日志会让数据偏悲观且不可比。
