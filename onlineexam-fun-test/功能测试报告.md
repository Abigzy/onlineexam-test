### 3.3 修复验证

- **BUG-01**：单题与批量共用 `PaperService._validate_score()`。`score=101` → 400/13004，`score=100` 仍允许，总分不再虚高。守门测试 `apps.papers.tests.test_defects` 9 条。
- **BUG-02**：`update()` 补 `ensure_editable`。已发布卷 PATCH → 400/13002，草稿仍可改。守门测试 4 条。
- **BUG-03**：`visible_student_ids()` 改 `order_by().distinct()`，`participation` 再兜底去重。`applicants=16`（原 17）。守门测试 4 条。
- **BUG-04**：`ScoreboardView` 改用 `data["results"]`。接口每条结果均带 `can_view_analytics`（教师看班外学生 = false，管理员 = true）；页面班外姓名渲染为纯文本、下钻链接 0 个。守门测试 `apps.grading.tests.test_defects` 4 条。
- **BUG-05**：新增 `AnswerStudentSerializer`（字段里根本没有 `reference_answer` / `analysis`），接口按 `is_teacher` 分流；学生看答案只能走交卷后的 `/result/`（受成绩公布门禁）。守门测试 `apps.exam.tests.test_answer_leak` 5 条：学生无答案 / 学生仍看得到自己的作答 / 响应体无答案文本 / 教师仍有答案 / 跨学生 404。
- **BUG-06**：`destroy()` 改用 `descendant_ids()` 覆盖整棵子树，`knowledge_points__id__in=子树 & is_active=True` 有题则 12030 拒绝；无题时级联删除并返回「含 N 个子知识点」。守门测试 `apps.questions.tests.test_questions` 3 条：子树含题拒绝（父子都不被删）/ 子树无题级联删除 / 停用题不阻塞。
- **BUG-07**：统一到 `ExamAttempt.score_visible()` 一个口径（`is_graded` 且 `show_score_immediately`）；`ExamAttemptStudentSerializer` 的 `score`/`passed` 改方法字段、未公开给 null；`_attempt_brief()` 的 `score` 同口径（卷面 / 续考 / 结果页三处一起修）；`AnswerStudentSerializer` 的 `is_correct`/`score`/`ai_score`/`ai_comment`/`teacher_comment` 同口径。守门测试 `test_answer_leak` 新增 6 条四阶段断言（作答中 / 刚交卷 / ensure_graded 未公开 / 已公开），`test_api_contract` 新增 2 条横切扫描。

七个缺陷的共性值得注意：**都是「同一规则两个入口，只拦了一个」「键名/口径约定不一致」或「校验范围算小了」**，不是复杂逻辑错误，属于重复实现与边界想窄导致的漂移。BUG-05 与 BUG-07 是一对：前者把答案出口开在了考试进行中，后者在修答案时只删了答案文本、没意识到「分数与对错」是同一件事的另一个出口——**修一个泄漏面之前，先列出所有能读出该信息的接口**。

## 6. 改进建议

按「防再发」优先级排列：

1. **同一业务的规则收敛到唯一入口**。BUG-01/02 都是「两个入口只拦一个」：建议把分值区间、可编辑状态这类不变式收进 service 层单一函数，视图与批量接口只能调用它，禁止各自实现校验。
2. **跨层键名用契约测试锁住**。BUG-04 是视图和服务层对返回键名各说各话：建议对「视图给服务层结果打标」这类场景加断言字段存在的接口测试（已补 4 条），并在评审时把返回结构写进接口文档。
3. **DISTINCT 与 Meta.ordering 的坑进团队 checklist**。BUG-03 的根因很隐蔽（`ordering` 参与 SELECT 导致 DISTINCT 失效），建议凡是用 `distinct()` 去重的地方一律先 `order_by()` 清空默认排序。
4. **破坏性接口变更需提前通知**。本轮「建学生必传 `grade_year`」会让旧脚本直接 400，建议纳入发布说明与对接方确认清单。
5. **冒烟脚本的时序断言改为轮询**。OBS-03 说明固定 sleep 在多轮回归里会制造假失败，回归脚本本身也需要稳定性投入。
6. **兼容性矩阵补齐**。当前 246 条里兼容性类只有 3 条且都是桌面 Chrome，建议至少补 Edge/Firefox 与 375px 两组冒烟。
7. **安全类用例要左移到提测门禁**。BUG-05 是在「接口自动化前的人工走查」才发现的，而它本可以由一条「学生视角字段白名单」的断言在每次回归里守住。**这条已落地**：`test_api_contract` 现在以学生身份扫全部可访问 GET 接口，答案类字段出现即失败、判分类字段未出分必须为空，放行要逐接口写明理由（BUG-07 就是这样被兜住的）。
8. **级联删除必须校验整棵子树**。BUG-06 的根因是「只校验自己」，这类问题的共同特征是「父子/主从结构 + CASCADE 外键」。建议凡是 CASCADE 删除的入口，统一先算 `descendant_ids()` 再判占用，并把「拒绝时要保证什么都没删」写成断言。
