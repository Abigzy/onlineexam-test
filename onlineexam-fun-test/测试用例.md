## 1. 测试用例设计说明

### 1.1 编写说明

本测试用例文档根据当前《需求分析与测试点》思维导图整理而成：先按模块把导图中的**正向测试点（应成功）**与**反向测试点（应被拒）**展开，再逐条补齐前置条件、测试步骤、测试数据与预期结果，形成可执行、可判定的用例，共 **246 条**（对应导图中 121 个正向测试点与 202 个反向测试点）。

覆盖范围与导图一一对应，包含：登录页面、注册页面（含学号派发）、个人资料、权限与越权、AI 适配层、知识点、题库管理（含导入与答案防泄漏）、试卷与组卷（含随机组卷）、在线考试（开考 / 计时 / 作答 / 交卷 / 防作弊）、判分与成绩（含成绩单与错题本）、学情分析、个性化推荐、作弊行为检测、班级管理、管理端、页面与交互，以及性能 / 安全 / 兼容性 / 可靠性等非功能项。

> 导图中的每个功能点在本文档中都有对应表格行；导图偏「验证什么」，本文档补全「怎么验、用什么数据、预期是什么」。

### 1.2 用例八大要素及其写法要求

| 要素 | 写法要求 |
| --- | --- |
| **用例编号** | `TC-<模块>-<序号>`，模块取两位模块号；同一场景的补充用例加字母后缀（如 TC-AUTH-08B）。编号全局唯一、不复用，删除用例后编号作废。 |
| **所属模块** | 用例归属的业务模块（15 个分组，对应需求规格的模块划分），用于按模块统计与分配执行人。 |
| **用例标题** | 一句话说清「验证什么」，采用「动作 + 对象 + 关键条件」写法，不写步骤、不写结论。 |
| **前置条件** | 执行前必须成立的环境与数据状态（登录身份、已有数据、配置开关）。达不到前置条件时用例不可判定，需先造数。 |
| **测试步骤** | 从用户或调用方视角的可执行动作序列，用 1) 2) 3) 编号；一步只做一件事，关键步骤标注预期观察点。 |
| **测试数据** | 步骤中用到的具体值（账号、id、参数、边界值）。禁止写「任意合法值」这类不可复现的描述。 |
| **预期结果** | 与步骤编号一一对应的可判定结论，必须能回答「通过 / 不通过」，包含状态码、业务码、页面表现或数据变化。 |
| **优先级** | P0 核心主流程 / P1 重要分支与异常 / P2 次要场景与体验。定义见 §1.5。 |

> 用例类型、需求编号、自动化方式、执行结果、缺陷编号、备注这 6 列保留在 Excel 中，用于追溯与执行登记，不重复放进本文档。

### 1.3 编号规则

`TC-<模块>-<序号>`，例如 `TC-AUTH-01`、`TC-EX-25`、`TC-AN-16`。同一场景下的补充用例加字母后缀（`TC-AUTH-08B` 表示「学号派发」的第二个子检查点）。编号一经分配不复用，删除的用例编号作废，避免历史测试报告指向错误的用例。

### 1.4 设计方法（按需求类型选）

| 需求类型 | 使用方法 | 本项目的落点举例 | 覆盖要求 |
| --- | --- | --- | --- |
| 输入域类需求 | 等价类划分 + 边界值分析 | 分值 0~100、时长 1~600 分钟、用户名 ≥3 位、题量 1~200 | 每个输入至少 1 个有效类 + 2 个无效类，并取 min-1/min/max/max+1 |
| 多条件组合 | 判定表 / 因果图 | 角色 × 资源归属 × 资源状态；open_to_all × 创建者 × 学生班级 | 列出条件桩与动作桩，逐列覆盖，避免漏掉「有权但状态不允许」的组合 |
| 业务流程 | 场景法 | 注册→建卷→发布→开考→交卷→判分→出分→看学情 | 基本流 1 条 + 备选流若干 + 异常流（断网、超时、AI 失败、并发） |
| 状态对象 | 状态迁移法 | 试卷 draft→published→archived；作答 in_progress→submitted→graded | 合法迁移逐条验证，非法迁移必须被拒（终态不回退） |
| 多参数组合 | 正交实验 | 浏览器 × 分辨率 × 角色 | 用正交表压缩到 9 组以内，保证两两组合覆盖 |
| 数据一致性 | 交叉校验 | 总分 = Σ 题分；已交 + 未交 = 应考；同一数字多入口 | 同一业务数字从多个入口取值比对，不一致即为缺陷 |
| 安全与权限 | 白名单 + 反向验证 | 学生视角字段、跨人访问、越权写操作 | 先断言「不该有的字段不存在」，再构造绕过页面直调接口的请求 |

### 1.5 优先级定义与覆盖策略

| 优先级 | 定义 | 执行要求 |
| --- | --- | --- |
| **P0** | 核心主流程，挂了系统不可用：注册登录、开考交卷、判分出分、权限边界 | 每次回归必跑，不允许带缺陷上线 |
| **P1** | 重要分支与异常：状态非法迁移、越权、边界值、AI 降级 | 每轮回归执行 |
| **P2** | 次要场景与体验：文案一致性、响应式、空状态、极端边界 | 版本发布前抽检或全量 |

覆盖策略：每个业务模块至少 1 条 P0；每条一级需求（FR-n）至少 1 条 P0；反向用例（异常 / 边界 / 权限 / 安全）占比不低于 30%，当前为 **45.9%**。反向用例优先于正向被覆盖——线上事故多数来自没人试过的非法输入。

### 1.8 准出标准

1. P0 用例通过率 100%，P1 通过率 ≥95%，P2 允许有记录的遗留项；
2. 无致命、严重级别缺陷；一般缺陷要么修复要么有明确的风险接受记录；
3. 自动化基线全绿：单测全过、冒烟 0 失败、内联 JS 0 失败、迁移无未生成变更；
4. 需求覆盖矩阵无空洞（每条 FR 至少 1 条用例）。

### 1.9 已知局限

- 兼容性只覆盖 Chrome 桌面端（1280 / 1440），Firefox 与移动端 375px 未系统验证；
- AI 输出的稳定性靠 mock + 阈值断言保证，真实模型的耗时与降级率只有抽样数据；
- 并发场景只覆盖注册撞号、并发交卷等关键点，未做全链路压测（见性能测试报告）。
