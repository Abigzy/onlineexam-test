## 2. 方法与口径

### 2.1 接口清单是怎么"找全"的

手工枚举必然漏，所以用例从**路由表**反推：

```python
for raw, pattern in _walk_patterns(get_resolver().url_patterns):
    if not raw.startswith("api/v1/"): continue
    ...  # 逐个 URLPattern 取 name / 支持的方法
```

两次必要的去重（都会让数字虚高，也都会让结论失真）：

1. **format 变体** —— DRF router 为每条路由额外生成 `.json` / `.api` 版本
   （`/api/v1/exams/^(?P<format>[a-z0-9]+)/?$`）。它们是同一个视图的不同内容协商
   方式，不是新接口。164 − 66 = 98。
2. **同址遮蔽** —— router 会在每个 include 前缀上挂 `APIRootView`。`/api/v1/users/`
   既是 `user-list` 又是 `api-root`，但前者先注册、后者**不可达**；`/api/v1/`
   则被 4 个 include 各挂了一个索引页。保留它们只会把 403 记到错的名字上。

另外 `ViewSetMixin.as_view()` 会自动往 action 映射里塞 `"head": "<同名 action>"`。
如果不过滤，矩阵会凭空多出一倍 HEAD 请求，而 HEAD 的响应体是空的、
断言只能读到 `None`——第一版就踩了这个坑。

### 2.2 三类检查的判定口径

**认证**：本项目的 `DEFAULT_PERMISSION_CLASSES` 是 `IsAuthenticated`，
所以除白名单外，匿名一律 401。白名单只有三条，写在
`PUBLIC_OPERATIONS` 里并被 `test_public_whitelist_is_exactly_three` 钉死
——**多放一条就是一处认证缺口**，用例会失败：

```
("register", "POST") ("login", "POST") ("refresh", "POST")
```

`/api/health/` 不在 `/api/v1/` 前缀下，由 `test_health_is_public` 单独确认。

**权限边界**：越权状态码**按各接口现有口径**断言，不强行统一。项目里有两套
刻意的口径，用例分别照抄：

| 资源类型 | 越权返回 | 理由 |
|---|---|---|
| 跨人 / 跨身份（考试、作答、成绩、学情、推荐） | **404** | 不拿 403 当「这个 id 存不存在」的探针 |
| 班级（id 不敏感） | **403 + code 14003** | 老师误点别人的班要看到「权限不足」，404 会让人以为班被删了 |
| 权限类直接拦截（`IsTeacher` / `IsAdmin` / `IsStudent`） | **403 + code 40300** | 根本没进视图，没有业务码可言 |

只有「真的写了契约」的几处被钉成具体元组（`EXPLICIT_DENY_CODES`），
其余按「403 或 404 都收」——**不为凑一个漂亮表格去改业务口径**。

**参数校验**：每个操作喂一组非法参数，断言 `status ∈ {400, 404, 422}` 且
`code ≠ 50000`。带路径参数的路由把 id 换成 `abc`；无参的列表接口追加
`?exam_id=abc&student_id=abc&attempt_id=abc&answer_id=abc&classroom_id=abc&page=-1&page_size=abc`。

### 2.3 隔离：每个操作跑完就回滚

矩阵里既有 `DELETE` 也有「交卷」「发布」这类改状态的动作。第一版没有隔离，
`classroom-detail DELETE` 把班级删掉之后，同一轮的 `GET` 全变成 404
——**矩阵看起来通过了，其实测的是「资源已被删除」**。现在每个操作都在
`transaction.atomic()` 里跑完即 `set_rollback(True)`，后一个操作永远看到
`setUpTestData` 那个干净世界。

### 2.4 双向校验：漏测与"测了不存在的接口"都会失败

`test_contract_covers_every_route` 做两件事：

* 路由表里有、准入清单里没有 → 失败（新增接口必须显式声明级别）；
* 准入清单里有、路由表里没有 → 失败（删了接口要同步删声明）。

这样这份矩阵不会随着时间悄悄烂掉。

## 5. 缺陷清单（真 bug，已修）

两类根因、共 6 个 500 场景。**都不是权限问题**（三种角色同时 500），
而是「正常路径没人走过」的边界。

### D-1 每日练习 POST：返回结构缺键 → KeyError → 500

* **接口**：`POST /api/v1/recommend/students/{id}/practice/`
* **复现**：一个**没有可练题目**的学生（例如没加入任何学科班）调用；`{}` 即可
* **现象**：500 / code 50000，学生、教师、管理员三种角色全中
* **根因**：`RecommendationService.explain()` 在 `items` 为空时提前返回的字典
  少了一个 `model` 键，而 `DailyPracticeView.post()` 直接
  `explained["model"]` 取值 → `KeyError`
* **修复**：`apps/recommend/services.py` 的提前返回分支补 `"model": ""`，
  并让该分支与完整分支**结构同构**（注释说明为什么必须同构）
* **回归用例**：`test_practice_post_without_candidates_returns_200`

### D-2 查询参数里的 id 未校验 → ValueError → 500

* **接口**（5 个，全部落在判分模块）：

  | 请求 | 修复前 | 修复后 |
  |---|---|---|
  | `GET /api/v1/grading/queue/?exam_id=abc` | **500** | 400 |
  | `GET /api/v1/grading/scoreboard/?exam_id=abc` | **500** | 400 |
  | `GET /api/v1/grading/wrong-book/?student_id=abc` | **500** | 400 |
  | `GET /api/v1/grading/feedback/?attempt_id=abc` | **500** | 400 |
  | `GET /api/v1/grading/feedback/?answer_id=abc` | **500** | 400 |

* **根因**：视图把 query 参数原样交给 `get_object_or_404(Model, pk="abc")`。
  Django 在 `queryset.get()` 阶段抛
  `ValueError: Field 'id' expected a number but got 'abc'`，而
  `get_object_or_404` **只捕 `DoesNotExist`**，这个 `ValueError` 一路冒到
  统一异常处理器 → 500。参数写错是客户端问题，必须 400。
* **修复**：`apps/grading/views.py` 新增 `_as_int(value, label)`，在 5 个入口
  统一转换，非法值抛 `BusinessError`（400）
* **回归用例**：`test_query_id_params_must_not_500`（含「一半合法一半非法」的
  组合 `?exam_id=1&classroom_id=abc`）

> 顺带确认**已经做对**的同类接口，作为对照：`grading/scoreboard?classroom_id=abc`
> 返回 404、`questions/?knowledge_point=abc` 返回 400、
> `recommend?...&size=abc` 返回 400、`proctoring/...?top_n=abc` 返回 400。
> 说明这不是「全局约定缺失」，而是判分模块漏了 5 处。

## 6. 权限口径观察（不是缺陷，但值得记录）

跑完矩阵后有几个**看着像不一致、实际是设计选择**的点，写在这里免得下次被
当成 bug 再查一遍：

1. `attempt-paper` / `attempt-save` / `attempt-heartbeat` / `attempt-behavior` /
   `attempt-submit` 是**仅学生**（`IsStudent`），教师访问得到 403 而不是「能看」。
   设计意图是「会产生作答数据 / 属于考生本人」的动作只给考生。
2. `attempt-answers` 的 GET 放给教师（批改用），POST 只给学生——同一路径两种
   身份，POST 由视图内部再卡一次（403 + code 10431）。
3. `exam-list` / `exam-detail` 的 GET 是 `IsAuthenticated`：教师看全部、
   学生只能看「已发布且在自己范围内」的，具体分流在 `get_queryset()` 里，
   不在权限类里挡人——挡了学生就看不到「我的考试」了。
4. 学生读**他人**的作答 / 成绩 / 学情 / 推荐一律 **404**，
   连「这个 id 存不存在」都不透露；`test_student_cannot_read_others_404` 专门钉死这条。
5. 反向证据：`test_student_can_read_own_resources` 确认学生读**自己**的这 10 个
   资源是 200。少了这条，「全员 404 也能全绿」。

## 8. 局限

1. **只测准入，不测业务**。矩阵断言的是「这个身份能不能进来、参数错了报什么」。
   业务分支（判分策略、组卷算法、推荐排序）仍由各模块的 1000+ 条用例负责，
   本文件不重复。
2. **准入清单是人工声明的**。`get_resolver()` 能保证「路由有的都测到」，
   但「教师该不该访问 `/analytics/exams/`」这种判断只能人来定。
   清单一旦写错，测试会和代码一起错——所以 §6 把几处刻意的口径都写清楚了，
   下次改权限前先读那一段。
3. **AI 一律走 mock**。`settings/base.py` 在 `"test" in sys.argv` 时把
   `AI_PROVIDER` 强制成 `mock`、清空所有 Key，因此测试不依赖外网、不烧额度，
   但也**不验证真实大模型返回异常格式时的降级路径**（那部分在
   `apps/recommend/tests/test_ai.py` 等文件里用假客户端覆盖）。
4. **未覆盖编辑器类长连接**（没有 SSE / WebSocket 接口），当前全站是普通 HTTP。
