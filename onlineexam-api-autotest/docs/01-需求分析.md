## 0. 结论摘要（先看这里）

1. **被测范围**：3 个角色 × 11 个业务模块，对外 **124 个 API 操作**（含健康检查），其中可直接用于自动化断言的约 **118 个**（5 个下载类接口返回非 JSON、1 个健康检查无业务语义）。
2. **P0 主链路共 10 条**：注册登录 → 知识点 → 题库 → 组卷 → 建考发布 → 学生作答（含断网续考/防切屏/交卷）→ 判分出分 → 学情分析 → 个性化推荐 → 作弊检测；班级管理是这些链路的**前置权限开关**，不能当边角料。
3. **最高风险不是功能缺失，而是"接口层可以绕过设计"**：`GET /api/v1/attempts/{id}/answers/` 会把参考答案与解析返回给正在考试的学生（详见 02 文档 D-03）。这条必须在执行阶段第一轮就验证，属于**致命级**候选缺陷。
4. **需求与实现有 1 处硬冲突**：知识点删除。需求/文档说"有子节点拒绝删除"，实现是"有题目拒绝、子节点级联删除"（02 文档 D-02）。不确认口径，相关反向用例的预期结果必然是错的。
5. **三处会直接影响自动化稳定性**：限流（auth 30/min、ai 20/min）、服务端时间权威（deadline/宽限 30s/每日练习按天）、AI 真实调用（当前 `.env` 指向 deepseek）。这三点必须写进测试计划的环境与数据策略，否则用例会"时好时坏"。

## 2. 业务全景

### 2.1 角色与权限边界

| 角色 | 能做什么 | 不能做什么（要重点验的边界） |
|---|---|---|
| 学生 `student` | 看自己范围内已发布考试、开考/暂存/心跳/行为上报/交卷/看结果、错题本、自己的学情与推荐 | 看不到未发布考试与他人考试；拿不到答案与解析；不能调任何配置类接口；跨人访问一律 404 |
| 教师 `teacher` | 知识点、题库、试卷、考试、判分、学情、监考、班级（自己创建/任班主任/授课的班） | 无任教学科时可管全学科；**有任教学科时被 `teacher_subject_scope` 收窄**；学情只能看自己班的学生（班外 404） |
| 管理员 `admin` | 全部业务 + 用户管理 + 系统总览 | 不能删除/停用自己；不能删除超级管理员；不能把最后一个启用管理员降级/停用 |

**三条容易踩的权限口径**（必须在用例里分开断言，不能统一按"404"写预期）：

1. **跨人敏感资源 → 404**：作答记录、成绩单、学情、推荐、用户。目的是不拿 403 当"这个 id 存不存在"的探针。
2. **班级资源 → 403**：`apps/classroom/views.py` 明确"班级 id 不敏感"，存在但无权限返回 `403 + code 14003`。
3. **考试"面向全体"→ 403**：班外学生 `POST /exams/{id}/start/` 返回 `403 + code 10431`；但列表里根本看不到该考试。

### 2.2 十条主链路（用例编排按此顺序）

| # | 链路 | 关键接口 | 数据前置 |
|---|---|---|---|
| L1 | 注册 / 登录 / 令牌 | `auth/register` → `auth/login` → `auth/refresh` → `auth/logout`；`auth/me`、`change-password` | 无（账号池） |
| L2 | 知识点树 | `knowledge-points/` CRUD → `tree/` → `{id}/questions/` | 教师账号、学科 |
| L3 | 题库 | `questions/` CRUD → `ai-generate` → `batch` → `import/export` → `statistics` | 知识点、学科 |
| L4 | 试卷与组卷 | `papers/` CRUD → `questions/remove-questions/scores/reorder` → `status` → `preview/analysis/export`；`ai-compose`/`random-compose`/`pool` | 题库有库存 |
| L5 | 建考与发布 | `exams/` CRUD → `status`（发布/开始/结束/归档）→ `candidates` | 已发布试卷、班级/学生 |
| L6 | 学生作答 | `exams/{id}/start` → `attempts/{id}/paper` → `save`/`answers` → `heartbeat` → `behavior` → `submit` → `result` | 考试处于可作答窗口 |
| L7 | 判分与成绩 | `grading/attempts/{id}/grade` → `answers/{id}/review` → `finalize` → `report`；`scoreboard`、`wrong-book`、`calibration` | 已交卷作答 |
| L8 | 学情分析 | `analytics/exams/{id}/report`、`analytics/exams/{id}/questions`；`students/{id}/mastery`、`trend`、`report`、`diagnosis` | 已出分作答 |
| L9 | 个性化推荐 | `recommend/students/{id}/practice/` GET / POST | 学生有答题历史（冷启动也要测） |
| L10 | 作弊检测 | `proctoring/exams/{id}/report`、`attempts/{id}/evidence`、`rules` | 有行为埋点的作答 |
| L0 | 班级（前置） | `classrooms/` CRUD + `students/` 增删 + `options` | 教师账号 |

### 2.3 三个状态机（用例必须覆盖"合法迁移 + 非法迁移"）

**考试**：`draft` → `published` → 结束 `finished` → `archived`。
注意 `ongoing`（进行中）**不落库**，由 `computed_status()` 按时间实时算；但 `status` 字段的枚举里又有 `ongoing`，且 `POST /exams/{id}/status/` 的 ChoiceField 接受全部枚举值——这是需要重点验证的模糊点（02 文档 D-09）。

**试卷**：`draft` ↔ `published` → `archived`。已发布的试卷不能删除（只能归档）；被考试引用的试卷不能换卷。

**作答**：`in_progress` → `submitted` →（自动判分）`auto_graded` / `reviewing` → `graded`；超时另有 `timeout` 标记与 `submit_reason`。总分只有一个写入口 `GradingService.recalc()`，幂等——这是"重复判分不叠加分数"用例的依据。

## 3. 功能需求拆解与可测点

> 「可测点」= 接口层能断言的观察量（状态码、code、字段、数据变化、可见性），不写"页面显示正确"这类不可断言的描述。
> 优先级：**P0** = 主链路 + 安全红线；**P1** = 重要分支与边界；**P2** = 统计/导出/低频能力。

| 模块 | 需求编号 | 接口数 | 核心正向可测点 | 关键反向可测点 | 优先级 |
|---|---|---|---|---|---|
| 认证与用户 | FR-1 | 18 | 用户名/邮箱/学号三种登录；注册派发学号（年级+顺位）；refresh 轮换；logout 后 refresh 失效；改密后旧 token 与新密码的行为 | 弱密码、两次密码不一致、用户名/邮箱重复、年级非法、停用账号、错误密码统一文案、无 token/过期 token | **P0** |
| AI 适配层 | FR-2 | 5 | providers 清单与 `is_current`；test-connection 成功/降级；chat 三种入参（messages/variables/prompt）；usage/logs 统计 | 无 Key 降级不报错；AI 异常 → 502 + `code 11001`；非教师访问 403；限流 429 | P1 |
| 知识点 | FR-3 | 8 | 建树（父子）、tree 返回嵌套、`{id}/questions/` 含子节点题目、排序 | 有题目时删除被拒（`code 12030`）；**有子节点时的删除行为待确认**；跨学科不可见 | **P0** |
| 题库 | FR-4 | 15 | 六种题型创建（选项/答案/解析/难度/分值）；筛选分页；AI 出题返回草稿不入库；批量入库；导入去重（`skipped_count`）；导出 | 选项缺失/答案与题型不匹配；导入空文件/错列/重复；删除=软删除（列表消失、历史卷仍可查）；学生访问 403 | **P0** |
| 试卷与组卷 | FR-5 | 20 | 三层结构；加题去重与停用题过滤；调分/排序后总分重算；发布/退回/归档；preview 按大题分组；analysis 知识点与难度分布；随机组卷 `dry_run` 不落库；同 seed 同结果 | 空卷发布被拒；已发布删除被拒；跨学科抽题被强制锁定；知识点无库存 → `code 13010`；非本人试卷越权（教师学科隔离） | **P0** |
| 在线考试 | FR-6 | 22 | 建考（指定考生/面向全体）；发布校验（空卷、草稿卷、次数<1）；start 返回卷面且**无答案字段**；断网续考题序一致；暂存/批量暂存；heartbeat 返回服务端剩余秒；behavior 计数与超限强制交卷；submit 幂等；result 受成绩可见性约束 | 未发布/未到时间/已结束开考；次数用完；班外学生 403；重复交卷；超时后暂存被拒；非本人 attempt 404；教师调 start 403 | **P0** |
| 判分与成绩 | FR-7 | 11 | 客观题纯函数判分（单选/多选三策略/判断/填空）；AI 批主观题；复核改分写审计；finalize 后学生可见；总分幂等重算；scoreboard 排名/及格率；错题本 | 未判客观题直接 finalize（防全班 0 分）；学生调判分 403；重复 grade 不叠加；复核分数越界；非本班学情 404 | **P0** |
| 学情分析 | FR-8 | 7 | 掌握度向上归并；薄弱判定（<0.60 且样本≥2）；趋势回归需 ≥3 点；班级分布/逐题得分率/区分度；GET 不调模型、POST 诊断走缓存 | 样本不足标 UNKNOWN；学生看他人 404；教师看班外学生 404；`classroom_id` 非自己班 404；`classroom_id=abc` 不 500 | **P0** |
| 个性化推荐 | FR-9 | 2 | 每日练习确定性（同日同学生同清单）；`offset` 换一批不重复；同知识点 ≤2 题；冷启动退化；POST 改写理由但选题不变 | 学生看他人 404；target 非学生 404；GET 不产生 AI 调用（用 `ai/logs` 反证）；AI 失败降级仍返回 200 | P1 |
| 作弊检测 | FR-10 | 4 | 规则目录 9 条；报告行含风险分/档位/命中规则/计数；证据链与计数核对；`only_suspicious`/`top_n` | `top_n=abc` → 400 不 500；学生访问 403；无埋点考试返回空而非报错；样本<8 不训练孤立森林 | P1 |
| 班级管理 | — | 10 | 建行政班/学科班；整班导入；按学号加人；成员列表；归档 | 非班主任改班 403（`14003`）；重复加人；非行政班整班导入被拒；学生建班 403；已归档班不可用 | **P0**（权限前置） |
| 管理端 | — | 1 | `system/overview` 指标齐全且与各列表口径一致 | 非管理员 403 | P2 |

**合计可测点 24 组**；预计用例规模 240–300 条（含正向约 45%、反向约 55%），第 4 步给出逐条用例。

## 4. 非功能需求分析（接口层视角）

| 编号 | 需求 | 接口层怎么验 | 风险 |
|---|---|---|---|
| NFR-1 | RESTful 语义 | GET 幂等（连续两次结果一致且无副作用）；PUT 全量、PATCH 局部；POST 非幂等；DELETE 幂等 | `ExamWriteSerializer` 字段全 optional，PUT 实际等同 PATCH → 需按实际记，不按语义记 |
| NFR-2 | 统一响应体 | 所有 JSON 接口都有 `code/message/data`；错误也带；`code=0` 才成功 | 下载类接口例外；405/429 也走信封 |
| NFR-3 | 答案防泄漏 | 学生侧任何响应都不含 `reference_answer` / `analysis` / `is_correct`（未出分时） | **已发现一条侧漏路径**（D-03） |
| NFR-4 | 越权 404 | 用 B 学生 token 访问 A 学生 attempt/成绩/学情 → 404 | 班级是 403 例外 |
| NFR-5 | AI 降级不抛异常 | 断网/无 Key/脏返回时业务接口仍 200，带 `degraded` / `is_mock` | 真实 provider 联网不可控，需 mock |
| NFR-6 | 参数校验 400 不 500 | 非法 id（`abc`）、超长字符串、缺必填、错误枚举 → 400 | `get_object_or_404(pk="abc")` 曾导致 500，已用 `_as_int` 兜底，需回归 |
| NFR-7 | 可复现 | 随机组卷同 `seed` 同结果；推荐同日同清单；异常检测 `random_state=42` | 依赖服务端时间/日期 |
| NFR-8 | 阈值集中 | 改 constants 影响面（本次不测代码，只测行为） | — |
| NFR-9 | 聚合避免 N+1、列表分页 | 分页参数边界（`page_size=0/101/abc`）；总数与翻页一致性 | 列表有两种形态（标准分页 / `{count,results}`），断言模板要分开 |
| NFR-10 | MySQL 5.6 兼容 | 中文/emoji 写入；JSON 字段以字符串存取 | 本地库版本与 CI 不一致会误报 |
| NFR-11 | 软删除可追溯 | 题目删除后：题库列表消失、历史试卷详情仍能取到题干 | 断言语义要写"列表不含、详情仍可" |
| NFR-12 | 学号/工号无唯一约束 | 并发注册撞号（已知局限） | 不做强断言，标注"已知局限"而非缺陷 |

## 5. 测试范围

### 5.1 范围内

- `/api/v1/` 下全部 124 个操作的**契约、权限、业务规则、边界与异常**。
- 统一响应体、分页、错误码、JWT 生命周期、限流（至少验证阈值存在与 429 形态）。
- 三条安全红线：答案泄漏、跨人越权、角色越权。
- 数据一致性：总分重算幂等、软删除可追溯、计数与明细一致（behavior vs evidence）。
- 可回归性：冒烟集（P0，约 60–80 条，5 分钟内跑完）+ 全量集。

### 5.2 范围外（本轮明确不做）

| 项 | 原因 | 后续建议 |
|---|---|---|
| 页面 UI / 交互 | 已由 `docs/UI走查清单.md` 与功能测试覆盖 | 需要时走 Selenium/Playwright 单独一轮 |

## 6. 风险清单（前置，按影响排序）

| 编号 | 风险 | 等级 | 影响面 | 建议动作 |
|---|---|---|---|---|
| R-01 | 学生可通过 `GET /attempts/{id}/answers/` 拿到参考答案/解析 | **致命** | 全站考试公平性 | 第一轮执行即验证；提致命缺陷；用例同时断言"考试中不可见" |
| R-02 | 限流（auth 30/min、ai 20/min）导致用例随机 429 | 高 | 登录类用例、AI 用例批量失败 | 账号池轮换 + 请求间隔；或经确认在测试环境放宽；用例显式断言 429 形态 |
| R-03 | 服务端时间权威（deadline / 30s 宽限 / 每日练习按天） | 高 | 超时交卷、续考、推荐清单 | 造数时用"当前时间 ±N 分钟"构造考试窗口，不写死日期；跨天用例单独标记 |
| R-04 | AI 真实调用（deepseek）产生费用与不确定性 | 高 | AI 出题、批改、诊断、推荐理由 | 优先走 mock/降级；限制调用次数；断言 `is_mock/degraded` 两态都通过 |
| R-05 | 测试数据相互污染（用户名/邮箱/学号全局唯一、次数上限、软删除） | 高 | 重复执行失败 | 统一前缀 `at_<ts>`；每次执行造新账号；只对自造数据做删除断言 |
| R-06 | 状态机顺序依赖（先发布试卷才能发布考试；先交卷才能判分） | 中 | 用例不可单独执行 | 用例按链路排序，或用 fixture 逐条造前置数据 |
| R-07 | 教师学科隔离（`teacher_subject_scope`）与班级范围交织 | 中 | 权限用例假阳性 | 用 `os_teacher` 与 `teacher` 两个账号分别验证"收窄"和"不收窄" |
| R-08 | 列表响应两种形态（标准分页 / `{count,results}`） | 中 | 分页断言误判 | 在用例里按接口分组维护两套断言模板 |

## 8. 需求可测性评价

**可测性好**：所有业务规则最终都收敛到接口的 `code` + 字段 + 可见性，且项目自带 1156 条单测与 196 项冒烟，业务语义有现成参照，不需要反向猜。

**可测性差的三处**（用例设计时要特别处理）：

1. **"进行中"是算出来的**：不能直接断言 `status == "ongoing"`，要断言 `computed_status` 与 `is_open`；构造时间窗才能稳定复现。
2. **AI 相关**：输出不可断言，只能断言"结构 + 降级 + 日志 + 缓存"四件事；真实 provider 联网时必须允许失败路径。
3. **前端才有的行为**：切屏、退出全屏、断网，接口层只能通过 `behavior` 上报模拟；"防切屏提醒"本身属 UI，本轮只验"上报后计数与强制交卷"。
