### 11.3 新发现：单题 `/save/` 仍会回滚自动收卷（BUG-03）

| 项 | 内容 |
|---|---|
| 现象 | 超宽限后调 `POST /attempts/{id}/save/`（单题）返回 `400/10400`，但作答状态仍是 `in_progress`；同一时刻调批量 `/answers/` 则已落成 `timeout` |
| 根因 | `ExamAttemptService.save_answer()` 带 `@transaction.atomic`，它内部调用 `save_answers()`（先 `resolve_expiry` 收卷）后抛 400，整笔事务回滚 → 收卷被撤销。批量视图直接调 `save_answers()`，没有外层事务，所以修复生效 |
| 影响 | 学生超时后若只触发单题保存（一屏一题模式每题切走都走这个接口），作答会停在"进行中"，直到心跳或交卷才结算；教师侧此时看到的是"进行中"，`finalize` 会被拒 |
| 严重度 | **一般**（数据未错，结算延后，有心跳兜底） |
| 回归用例 | `test_b9_edges.py::test_save_single_after_grace_settles_attempt`（`xfail(strict=True)`） |
| 建议 | 把 `save_answer()` 的事务去掉（或改为只包住"读取最新答案回显"那一步），与批量入口保持同一事务边界 |
