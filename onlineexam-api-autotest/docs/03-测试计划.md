> 依据：`01-需求分析.md`、`02-接口文档分析与评审.md`（含 §10 V2 复核）、`onlineexam-fun-test` 既有交付

## 1. 背景与目标

### 1.1 背景

1. 系统已完成 11 个业务模块开发，后端单测 1164 条、端到端冒烟 196 项、内联 JS 26 块全绿。
2. 功能测试已完成：`onlineexam-fun-test` 交付 243 条用例（全通过）、6 个缺陷闭环（含答案泄漏、知识点级联删除两个严重问题）。
3. 接口契约矩阵已完成：124 个操作 × 4 种身份 + 非法参数，661 条断言，2 个根因（6 个 500 场景）已修。
4. **缺口**：上述测试以"功能操作路径"和"准入检查"为主，缺少一套**可重复执行、面向业务规则与数据一致性**的接口自动化回归集。每次改代码仍要靠人工重跑 243 条用例与 15 条契约用例，成本高、易漏。

### 1.2 目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G-1 | 核心业务规则在接口层被钉死 | 判分三策略、组卷约束、次数上限、状态机非法迁移等规则，每条至少 1 条自动化断言 |
| G-2 | 主链路可一键回归 | 冒烟集（约 30 条）≤5 分钟跑完，覆盖 10 条主链路的"能通" |
| G-3 | 安全红线可回归 | 答案/解析/对错不泄露、跨人 404、角色 403，形成横切断言集 |
| G-4 | 数据一致性可验证 | 总分重算幂等、行为计数与证据链一致、软删除可追溯 |
| G-5 | 产出可复用资产 | 接口封装层 + 数据工厂 + 用例集 + 报告模板，后续迭代直接复用 |

### 1.3 非目标

- 不追求"发现更多缺陷"的数量指标；本轮以**建立可回归基线**为首要目的。
- 不替代功能测试与单测；不评价 AI 输出质量；不做代码修复。

## 3. 测试策略与类型

### 3.1 分层策略

| 层 | 名称 | 内容 | 数量 | 执行频率 |
|---|---|---|---|---|
| L0 | 冒烟层 | 健康检查 + 5 个账号登录 + 10 条主链路"能通" | ~30 | 每次提交 / 每日 |
| L1 | 单接口业务层 | 一个接口的多条业务分支（合法值、边界、业务拒绝码） | ~110 | 全量回归 |
| L2 | 场景层 | 跨接口串联，验证状态流转与数据传递 | ~30 | 全量回归 |
| L3 | 一致性与幂等层 | 重算、重复动作、计数核对、软删除 | ~20 | 全量回归 |
| L4 | 安全横切层 | 字段白名单、越权、角色边界 | ~15 | 每次提交（与 L0 同跑） |

### 3.2 设计方法映射

| 方法 | 用在哪 |
|---|---|
| 等价类 + 边界值 | 分值（0/0.5/100/100.5）、题量（0/1/库存上限/超库存）、`page_size`（1/100/101）、密码长度（5/6/7）、`max_attempts`（1/2/10/11） |
| 判定表 | 判分：题型 × 作答（全对/漏选/错选）× 策略（strict/partial/penalty） |
| 状态迁移 | 考试 5 状态 × 6 迁移动作；试卷 3 状态；作答 6 状态 |
| 场景法 | 开考→暂存→心跳→行为→交卷→判分→出分→学情→推荐→监考 |
| 正交/组合 | 考试配置（乱序题 × 乱序选项 × 防切屏 × 立即公布）× 学生行为 |
| 错误推测 | 重复提交、并发开考、跨班学生、已停用题目、已归档试卷、AI 返回脏数据 |

### 3.4 自动化实现方案（第 5 步落地）

```
onlineexam_api_autotest/
├── common/
│   ├── config.py        # 环境配置（base_url、账号、超时、开关）
│   ├── client.py        # requests 封装：统一信封解析、日志、耗时、重试策略
│   ├── auth.py          # 5 个账号的 token 获取/缓存/刷新
│   ├── assertor.py      # 双断言（HTTP + code）、字段白名单、分页两套模板
│   └── db.py            # 只读校验 + 受限写（改 deadline_at 造超时）
├── encap_api/           # 按业务域封装：auth/users/questions/papers/exams/grading/...
├── data/                # 账号池、用例数据 yaml、导入样本 csv/xlsx
├── scripts/             # 造数（班级/知识点/题目/试卷/考试）、清理
├── tests/               # test_l0_smoke ... test_l4_security
├── log/                 # 每次运行一份 request/response 全量日志
└── report/              # pytest-html / junit xml
```

**选型理由**：pytest 的参数化与 fixture 适合"同一接口多组数据"；requests 足够覆盖纯 HTTP 接口；不引入 Selenium（UI 不在范围）。报告先用 pytest-html（零额外依赖），需要时再加 Allure。

### 3.5 断言策略

1. **双断言**：`HTTP status` + `code` 必须同时匹配；禁止只断言 `code==0`。
2. **禁 500**：任何用例出现 500 即失败，且单独标记（参数类必须 400）。
3. **字段白名单**：学生视角响应做"不得出现"断言（`reference_answer`、`analysis`、未出分时的 `is_correct/score`），并对整段响应体做关键字扫描。
4. **结构断言**：分页按 A/B 两套模板；列表 `count == len(results)`（形态 B）或 `total_pages` 自洽（形态 A）。
5. **数据断言**：只在必要时查库（如 `deadline_at` 造数、`is_correct` 落库），业务结论优先进口响应；查库用只读连接。
6. **容错**：AI 相关用例允许 `is_mock=True` 或 `degraded=True` 两种通过路径，但必须二者之一。

### 4.2 账号池

| 账号 | 角色 | 用途 | 备注 |
|---|---|---|---|
| `admin` | 管理员 | 用户管理、系统总览、全局权限 | 不可删/停用自己 |
| `teacher` | 教师（无学科限制） | 组卷、建考、判分 | 主教师 |
| `os_teacher` | 教师（操作系统） | 学科隔离验证 | 只能看自己学科 |
| `student` / `s_001` | 学生 | 作答主链路 | 需在考试范围内 |
| `s_002`（或新建） | 学生（班外） | 班外开考 403、跨人 404 | 必须在另一个班 |
| `at_stu_<ts>` | 新建学生 | 注册/学号派发/删除类用例 | 每轮新建，避免唯一约束冲突 |

> 密码统一 `Exam@123456`；新账号用 `at_` 前缀，执行后停用不物理删除。

### 4.3 数据工厂（造数顺序）

| 步骤 | 造什么 | 关键约束 | 复用策略 |
|---|---|---|---|
| 1 | 行政班 + 学科班 | 学科班可挂靠行政班 | 每轮 1 个，跑完归档 |
| 2 | 学生入班 | 学生必须入班才被教师"看见" | 用 `s_001`/`s_002` |
| 3 | 知识点（2 层） | 父子结构，验证归并与级联 | 每轮新建 `at_kp_<ts>` |
| 4 | 题目（6 题型） | 每题型 × 难度至少 1 道，含 1 道主观题 | 每轮 10–15 道 |
| 5 | 试卷 + 加题 + 发布 | 分值合计 100，含客观与主观 | 每轮 1 份 |
| 6 | 考试（指定/全体各 1 场） | `start_time=now-5m`、`end_time=now+30m`、`duration=20`、`max_attempts=2` | 每轮 2 场 |
| 7 | 作答 | 学生 A 交卷、学生 B 进行中 | 每轮 2 条 |
| 8 | 判分/出分 | 先客观、再 AI（mock）、后 finalize | 每轮 1 条 |

**清理策略**：题目软删除；试卷/考试/班级归档；用户停用；**不物理删除**（保护历史与演示数据）。所有名称带 `at_<yyyyMMddHHmmss>`，执行后可按前缀识别。

### 4.4 时间与 AI 的控制

| 场景 | 做法 | 禁止 |
|---|---|---|
| 超时交卷 | 直接改 `deadline_at` 到过去（受限写库），再调 `submit` | `sleep` 等满考试时长 |
| 宽限期 30s | `deadline_at = now - 10s` → 仍可交卷；`now - 40s` → 判定超时 | 卡点跑，不稳定 |
| 未开始/已结束 | 建考时把 `start_time` 设未来 / `end_time` 设过去 | 改系统时间 |
| 每日练习跨天 | 只验"同一天确定性"，跨天用单测覆盖（接口层不伪造日期） | 改服务器时间 |
| AI 相关 | 不传 `with_ai`；必须验时用 `provider=mock` | 批量真实调用 |

### 6.2 准出标准

| 层级 | 标准 |
|---|---|
| 冒烟（L0） | 100% 执行、100% 通过，≤5 分钟 |
| 全量 | 执行率 100%；P0 通过率 100%；P1 通过率 ≥95% |
| 缺陷 | 无致命/严重未闭环；一般缺陷有明确结论（修复/延后/接受） |
| 一致性 | 关键数据断言（总分、计数、可见性）全部通过 |
| 可回归 | 一条命令复跑；失败用例有报文与日志 |
| 交付 | 用例、脚本、执行记录、缺陷单、报告齐全 |

### 6.3 暂停/中止条件

- 服务不可用或错误率 >20% 持续 30 分钟；
- 测试库被污染（演示数据被改）且无法回滚；
- 阻塞级缺陷 >3 个导致主链路不可执行；
- 环境与生产差异导致结论不可信（如 MySQL 版本/字符集不一致）。
