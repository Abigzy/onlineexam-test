## 4. 工程结构

```
onlineexam_api_autotest/
├── config.py                   # 常量入口：BASE_DIR / BASE_URL / 账号 / TEST_PREFIX
├── pytest.ini                  # testpaths=scripts；--html=report/report.html
├── conftest.py                 # 角色客户端 + 常用 ID fixture
├── common/
│   ├── config.py               # 运行期配置：地址、账号池、超时、at_ 前缀
│   ├── client.py               # requests 封装：信封解析、日志、耗时、trust_env=False
│   ├── auth.py                 # 登录 + token 池（防限流）
│   ├── assertor.py             # 双断言、禁 500、敏感字段扫描、分页 A/B 模板
│   ├── assert_tools.py         # 公共断言 CommonAssert（common_assert）
│   ├── get_data.py             # JSON 数据驱动：read_login_data()
│   ├── get_token.py            # token 获取与请求头（get_token/get_headers）
│   ├── logging_use.py          # 日志初始化 init_log_config（按天切分）
│   └── db_tools.py             # pymysql：query_db / db_uid（改 deadline_at 造超时）
├── encap_api/
│   ├── base.py                 # 路径拼接与动词转发
│   ├── auth_user_api.py        # AuthApi / UserApi
│   ├── content_api.py          # KnowledgeApi / QuestionApi / PaperApi
│   ├── exam_api.py             # ExamApi / AttemptApi
│   ├── grading_api.py          # GradingApi
│   ├── insight_api.py          # AnalyticsApi / RecommendApi / ProctoringApi
│   └── admin_api.py            # ClassroomApi / AiApi / SystemApi
├── data/
│   ├── accounts.yaml           # 账号池
│   └── login_data.json         # 登录用例数据（JSON 数据驱动）
├── scripts/                    # 用例目录
│   ├── check_env.py            # 环境自检
│   ├── test_auth_login.py      # 数据驱动登录
│   └── test_l0_smoke.py        # 27 条只读冒烟
├── log/                        # onlineexam.log（按天切分）+ api_<ts>.log
└── report/                     # report.html（pytest-html）
```

设计取舍：

1. **失败不抛异常**：HTTP 4xx 是"可断言的结果"，只有网络层异常才中断——否则"断言 401"会变成"测试报错"。
2. **忽略系统代理**：`session.trust_env = False`（见 §6.1），否则本机请求会被 `HTTP_PROXY` 转发成绝对 URI，Django 直接 404。
3. **接口封装不做断言**：断言集中在 `assertor` 与用例里，封装层保持薄，便于用例复用同一接口的不同断言。

## 6. 环境问题与处置（踩坑记录）

### 6.1 `HTTP_PROXY` 导致全站 404（已修）

- **现象**：首次跑冒烟 13 条失败、4 条 fixture 报错，服务端日志显示请求行是
  `GET http://127.0.0.1:8777/api/v1/questions/ HTTP/1.1`，Django 报 `Not Found: /http:/127.0.0.1:8777/...`。
- **根因**：环境变量 `HTTP_PROXY=http://127.0.0.1:49674`（本机代理工具），`requests` 默认 `trust_env=True`，
  把本机请求也走代理；代理以**绝对 URI** 转发，Django 的 URL 解析器不认，于是 404。
- **修复**：`ApiClient.__init__` 设 `self.session.trust_env = False`。
- **影响面**：所有接口自动化项目在本机跑都可能踩到；已写进 `client.py` 注释。

### 6.2 解释器不一致

全局 `python`（3.13.14）没有 requests/pytest，直接用会 `ModuleNotFoundError`。
统一使用 `OnlineExam/.venv/Scripts/python.exe`；如需独立环境，新建 venv 后装
`requests pytest PyYAML`（约 15MB）即可。

### 6.3 限流

`auth` 30/min：6 个账号 + 冒烟里的参数化登录共 11 次，未触发。
全量执行时若同一账号重复登录（如改密用例），需用独立账号或错峰：

```bash
API_PWD_ALIAS=...  # 仅覆盖口令，不改变登录次数
```

### 6.4 数据范围与可见性

`teacher` 账号在演示库可见 766 题 / 3 试卷 / 4 考试，低于数据库总量（1988 / 8 / 24）
——这是 `teacher_subject_scope` 的正常收窄，不是环境缺失。写用例时不要假设"教师看到全部"。

### 6.5 演示库已有脏数据痕迹

学生作答 `submit_reason_display` 出现 `学生ä¸...` 这类乱码（历史造数编码问题）。
接口层不影响断言（我们断言 `status/code` 与关键字段），但**报告里不作为缺陷**，只记为数据质量观察。

### 10.2 保留的差异（有意为之）

| 项 | 常见写法 | 本项目 | 原因 |
|---|---|---|---|
| 响应断言 | `success + code + message` | `code + message + data`，`success` 由 `code==0` 推导 | 被测系统统一信封没有 `success` 字段 |
| 请求封装 | 每个接口函数直接 `requests.post` | `ApiClient` 统一会话/日志/信封解析 | 264 条用例需要统一证据链与耗时统计 |
| token | 每次调用重新登录 | session 级缓存 | `auth` 限流 30/min，重复登录会 429 |
| 断言工具 | 一个 `common_assert` | `assert_tools`（公共断言）+ `assertor`（敏感字段/分页/禁 500） | 安全类断言需要递归扫描响应体 |
| 用例目录 | `scripts/` | `scripts/`（已对齐） | 原 `tests/` 已迁移，`conftest.py` 放到根目录 |
