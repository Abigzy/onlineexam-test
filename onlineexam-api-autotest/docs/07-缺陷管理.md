## 二、缺陷单

### BUG-01 成绩可见性存在两套口径：成绩单已公开答案，作答明细仍为 null

| 项 | 内容 |
|---|---|
| **缺陷标题** | 同一份已出分作答，`GET /grading/attempts/{id}/report/` 返回 `visible=true`、总分与参考答案，而 `GET /attempts/{id}/answers/` 的 `is_correct/score` 仍为 `null` |
| **环境/版本** | `http://127.0.0.1:8777`；`OnlineExam.settings.development`；2026-11-03 提测版；MySQL 5.6.46 |
| **前置数据** | 考试 `show_score_immediately=false`；学生 A 已交卷；教师已执行 `grade` + `finalize`（状态 `graded`） |
| **复现步骤** | 1. 用学生 A 登录，`POST /api/v1/exams/{exam_id}/start/` 取 attempt_id<br>2. `POST /api/v1/attempts/{id}/save/` 答对单选，`POST /submit/` 交卷<br>3. 教师 `POST /api/v1/grading/attempts/{id}/grade/`，再 `POST /finalize/`<br>4. 学生 `GET /api/v1/grading/attempts/{id}/report/`<br>5. 学生 `GET /api/v1/attempts/{id}/answers/`，对比同一题 |
| **预期结果** | 按接口文档 §2.F「唯一口径 `ExamAttempt.score_visible()`」：`show_score_immediately=false` 时，学生侧所有接口的得分与逐题对错一律为 `null`；两个接口的可见性结论必须一致 |
| **实际结果** | 成绩单：`visible=true`、`score=2.0`、`items[0].reference_answer="A"`、`is_correct=true`、`analysis="at_…解析"`；作答明细：`is_correct=null`、`score=null`、无 `reference_answer`。**同一份作答、同一时刻，两个接口结论相反** |
| **严重程度** | **严重**（涉及答案/解析口径，且与"唯一口径"的文档承诺冲突） |
| **优先级** | 高 |
| **影响范围** | 全部"教师已出分但考试未开启立即公布"的场景；前端两个页面（成绩单页 / 答卷明细）会给出矛盾结论；若产品意图是"未公布不展示"，则成绩单提前下发了参考答案与解析 |
| **附件** | 请求/响应证据见 §2.1；日志 `log/api_<ts>.log`；回归用例 `scripts/test_l0b_flow.py::test_report_and_answers_visibility_consistent` |
| **复现率** | **3/3**（三次独立造数均复现） |
| **状态** | **已关闭**（2026-11-03 修复并回归） |

#### 2.1 证据报文

200 {"code":0,"data":{

200 {"code":0,"data":{"results":[{

      "is_correct": null,

      "ai_score": null
      # 无 reference_answer / analysis

> 考试 48 的 `show_score_immediately=false`（开考响应 `config.show_score_immediately` 实测为 false）。

#### 2.2 根因（定位线索，不替代开发修复）

项目里有**两个同名不同实现**的可见性判断：

| 位置 | 规则 | 使用方 |
|---|---|---|
| `apps/exam/models.py::ExamAttempt.score_visible()` | `is_graded and exam.show_score_immediately` | 学生列表/详情、`_attempt_brief`、`AnswerStudentSerializer`（逐题对错/得分） |
| `apps/grading/services.py::ScoreReportService.score_visible()` | `status == GRADED` → 恒 true；`AUTO_GRADED` → 看开关 | 成绩单 `AttemptReportView` |

`finalize` 把状态推进到 `GRADED` 后：

- 成绩单走后者 → `visible=true`，于是 `items` 里补上 `reference_answer`、`analysis`、`is_correct`、`score`；
- 作答明细走前者 → `is_graded && show_score_immediately = false`，字段被置空。

两个函数各自内部自洽，合起来就矛盾。功能测试 246 条未覆盖"同一时刻对比两个接口"这种横切场景，因此没被发现。

#### 2.3 修复建议（两选一，需产品先定口径）

**口径 A：出分即公开（与需求 FR-7-10「`graded` 必可见」一致）**

1. 把 `ExamAttempt.score_visible()` 改为：
   `status == GRADED or (status == AUTO_GRADED and exam.show_score_immediately)`；
2. `ScoreReportService.score_visible()` 直接调用它，删除重复实现；
3. `/attempts/{id}/answers/`、`/result/`、`exams/` 内嵌 `my_attempt` 自动跟随；
4. 同步接口文档 §2.F 的"唯一口径"描述。

**口径 B：仍受「立即公布」开关控制（与接口文档一致）**

1. `ScoreReportService.score_visible()` 改为调用 `ExamAttempt.score_visible()`；
2. 成绩单在 `visible=false` 时把顶层 `score/objective_score/subjective_score` 置 0 或 `null`，`items` 不补答案字段；
3. 同步需求 FR-7-10 的表述。

> 无论选哪个，**唯一口径必须只保留一处实现**；本次缺陷的本质就是"同一规则写了两遍"。

#### 2.4 回归验证

- 回归用例：`test_report_and_answers_visibility_consistent`（当前 `xfail(strict=True)`，reason 指向 BUG-01）。
- 修复后该用例应转为 pass；若是口径 A，还需把 `test_score_hidden_before_publish` 的预期从"null"改为"可见"，并在用例文档中同步。

## 六、第三批新增缺陷（2026-11-03 20:20）

### BUG-02 批量暂存答案时 items 内重复题目导致 500，整批答案全部丢失

| 项 | 内容 |
|---|---|
| **缺陷标题** | `POST /api/v1/attempts/{id}/answers/` 的 `items` 中同一 `paper_question_id` 出现两次时，服务端未去重直接落库，触发唯一键冲突 `uniq_answer_attempt_question` → `500/50000`，且整批答案（含合法的那些）一起回滚 |
| **环境/版本** | `http://127.0.0.1:8777`；`OnlineExam.settings.development`；2026-11-03 提测版；MySQL 5.6.46；DRF 3.16.1 |
| **前置数据** | 学生 A 在已发布考试中处于 `in_progress`；试卷含 6 题（`paper_question_id` 781–786） |
| **复现步骤** | 1. 教师建考试并发布，指定学生 A；<br>2. 学生 A `POST /api/v1/exams/{exam_id}/start/`，记录 attempt_id；<br>3. 学生 A `POST /api/v1/attempts/{attempt_id}/answers/`，请求体：<br>`{"items":[{"paper_question_id":786,"selected_labels":"A"},{"paper_question_id":786,"selected_labels":"B"}]}`<br>4. 观察响应与作答明细 |
| **预期结果** | 二选一均可接受：① 服务端按 `paper_question_id` 去重（后者覆盖前者或取首条），返回 `200/C0` 并保存 1 条；② 明确拒绝重复条目，返回 `400` 并说明哪个 id 重复。**不允许 500** |
| **实际结果** | `500`，响应体 `{"code":50000,"message":"服务器内部错误，请稍后重试或联系管理员","data":null}`；随后 `GET /attempts/{id}/answers/` 明细为空——**整批答案一条都没落库**（事务回滚） |
| **服务端根因** | `apps/exam/views.py:393` 直接把 `serializer.validated_data["items"]` 交给 `ExamAttemptService.save_answers()`；该函数按 items 逐条 upsert，同一 `paper_question_id` 第二次插入撞唯一键 `uniq_answer_attempt_question`，抛 `IntegrityError` 未被捕获，最终由统一异常处理器兜成 500：<br>`IntegrityError: (1062, "Duplicate entry '76-786' for key 'uniq_answer_attempt_question'")` |
| **严重程度** | **严重**（服务端 500 + 已作答数据整批丢失，属数据一致性风险） |
| **优先级** | 高 |
| **影响范围** | ① 前端「自动保存」与「手动保存」并发或网络重试时，同一题可能在同一批次里出现两次 → 学生本次提交的全部答案丢失；② 弱网/重复点击场景可稳定命中；③ 若前端未做本地兜底，学生以为已保存，实际交卷时该批答案为空 |
| **附件** | 服务端堆栈（`logs/django.log` 与控制台）；回归用例 `scripts/test_b9_edges.py::test_batch_save_duplicate_items_not_500`（`xfail(strict=True)`）；日志 `log/api_<ts>.log` |
| **复现率** | **3/3**（2 条重复即 100% 复现，与题量无关） |
| **建议修复** | 在 `save_answers()` 入口按 `paper_question_id` 做一次有序去重（保留最后一次，符合"后写覆盖"直觉），并给 `bulk_create(..., ignore_conflicts=True)` 或 `update_or_create` 兜底；同时补单测：同 id ×2、同 id ×N、混合批次 |
| **状态** | **已关闭**（2026-11-03 修复并回归，见 §6.4） |

#### 6.2 与 BUG-01 的关系
