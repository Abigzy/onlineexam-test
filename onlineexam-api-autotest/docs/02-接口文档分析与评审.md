## 0. 评审结论

**结论：文档可以作为测试依据，但不能直接照抄预期结果。** 有 3 个**阻断项**必须先定性，否则用例写出来就是错的：

1. **D-01 文档漏了 12 个接口**（班级 10、系统总览 1、题库科目分类 1）。按文档设计用例，会整块漏测班级权限——而班级恰恰是考试范围、学情范围的前置开关。
2. **D-02 知识点删除的语义，文档/需求与代码相反**。文档说"有子节点拒绝"，代码是"有题目拒绝、子节点级联删除"。
3. **D-03 存在一条答案侧漏路径**：学生本人可 `GET /attempts/{id}/answers/` 拿到 `reference_answer` 与 `analysis`，与"答案过滤只有一处出口"的设计注释直接冲突。

另有 11 项口径类差异（HTTP 状态、分页形态、限流、403/404 例外、下载接口、PUT 语义等），不阻断设计，但会让"想当然的断言"批量失败。

**数量核对（V1 评审时口径，V2 复核见 §10）**：

| 口径 | 数量 | 说明 |
|---|---|---|
| 文档标称 | 125 | 文首写"共 125 个接口操作，覆盖 11 个分组" |
| 文档正文实际列出 | **112**（含 `/api/health/`） | 把 PUT/PATCH 合并成一行的按 2 个算 |
| 真实实现（OpenAPI） | **124**（含 `/api/health/`） | GET 61 / POST 42 / PUT 7 / PATCH 7 / DELETE 7 |
| 差额 | **+12** | `classrooms/*` 10 个、`system/overview` 1 个、`questions/subjects` 1 个 |

> 也就是说：标称 125 与正文 112、与真实 124 三者都不一致。**以 124 为准**（`assets/接口操作清单-124.txt`）。

### 2.2 口径类差异（影响断言写法）

| 编号 | 主题 | 文档说法 | 实际行为 | 测试侧处置 |
|---|---|---|---|---|
| D-04 | HTTP 状态 vs 业务码 | "业务错误也返回 200 信封 + 非零 code（除框架级异常外）" | 登录失败 `401/40100`、账号停用 `401/40101`、班外开考 `403/10431`、班级无权 `403/14003`、越权资源 `404/40400`、参数错 `400/40000`、AI 异常 `502/11001` | 双断言：`HTTP status` + `code`；成功判定仍只看 `code==0` |
| D-05 | 列表分页 | "列表类接口一律分页，不返回裸数组" | 两种形态并存：① DRF 标准分页（users、questions、papers、exams、attempts、knowledge-points、ai/logs、grading/feedback）；② 手写 `{count, results}` 不分页（classrooms、classrooms/options、grading/exams、grading/scoreboard、analytics/exams、proctoring/exams、exams/{id}/attempts、exams/candidates、ai/usage、questions/subjects、questions/statistics） | 维护两套断言模板；分页参数只对①断言 |
| D-06 | 限流 | 给速率表，未给 429 响应结构 | 超限 → `429`，经渲染器包 `code 42900`；仅 auth/ai 两个 scope | 显式用例验证 429 形态；批量执行时做账号轮换与限速 |
| D-07 | 越权状态码 | "跨人访问返回 404 而非 403" | 班级例外：存在但无权 → `403/14003`；用户/成绩/学情/推荐仍是 404 | 用例按资源类型写预期，不统一套 404 |
| D-08 | 文件下载 | "所有接口（含报错）都是统一信封" | `questions/export`、`questions/import-template`、`papers/{id}/export` 返回 `xlsx/csv/html/md` 流，无信封 | 单列 3 条文件类用例，断言 `Content-Type` / `Content-Disposition` / 文件魔数 |
| D-09 | 考试状态 | 五状态，含"进行中按时间实时算" | `status` 枚举含 `ongoing`，`POST /exams/{id}/status/` 的 ChoiceField 接受全部枚举；`change_status` 另有迁移白名单 | 正向只走 `published/finished/archived`；单独一条验证 `status=ongoing` 的实际结果，再定性 |
| D-10 | PUT 语义 | "PUT 全量、PATCH 局部"（NFR-1） | `ExamWriteSerializer`/`PaperWriteSerializer` 字段全 `required=False`，PUT 只传一个字段也会成功 | 用例记录实际行为；不按"PUT 缺字段应 400"写预期 |
| D-11 | 教师数据范围 | 多处笼统写"教师" | 学情：教师只能看**自己带的班**（班外 404，`analytics/scoping.py`）；推荐：教师可看**任意学生**（不校验班级）；grading/exams 列表：非管理员只看 `created_by=self` | 三个口径分开断言；推荐是"更宽"的例外 |
| D-12 | `attempts` 列表可见性 | "我的作答列表｜登录" | 教师 `get_queryset` 返回**全部**作答；学生只看自己 | 教师视角用例断言"能看到他人作答"，学生断言"只有自己" |
| D-13 | 注册角色 | "角色由服务端决定" | `role` ChoiceField 只允许 `student`；传 `teacher` → `400` + `invalid_choice`（"教师账号由管理员创建"） | 反向用例：注册传 `role=teacher` 必须 400 |

## 3. 统一契约测试要点（每条接口都要过的"公共关"）

### 3.1 响应信封

- 成功：HTTP 200/201，`code == 0`，`message` 非空，`data` 结构符合文档。
- 失败：HTTP 4xx/5xx，`code == HTTP 状态 ×100`（业务异常除外，用模块自定义码），`data` 为 `null` 或字段级错误字典。
- 列表：不是裸数组（除文档明确的下载接口），至少含 `count` + `results`。

### 3.2 状态码与错误码矩阵（实测预期）

| 场景 | HTTP | code | 备注 |
|---|---|---|---|
| 创建成功 | 201 | 0 | `created()` |
| 查询/更新成功 | 200 | 0 | `success()` |
| 删除成功 | 200 | 0 | 项目统一 200，不是 204 |
| 未带 token | 401 | 40100 | DRF `NotAuthenticated` |
| token 过期/伪造 | 401 | 40100 | SimpleJWT `InvalidToken` |
| 登录失败 | 401 | **40100** | 统一文案"账号或密码错误" |
| 账号停用 | 401 | **40101** | 密码正确才给停用提示 |
| 角色不足 | 403 | 40300 | `IsTeacher/IsAdmin` 的 `message` |
| 班外开考 | 403 | **10431** | `BusinessError` 指定 |
| 班级无权 | 403 | **14003** | `CLASSROOM_PERM_DENIED` |
| 跨人资源 | 404 | 40400 | 不给存在性探针 |
| 参数校验失败 | 400 | 40000 | `data` 含字段级错误 |
| 业务规则拒绝 | 400 | 模块自定义（如 12030/13010/10014） | `message` 可直接展示 |
| 方法不允许 | 405 | 40500 | 走同一渲染器 |
| 限流 | 429 | 42900 | 仅 auth/ai |
| AI 调用失败 | 502 | 11001 | `ai/chat` 专属 |
| 未捕获异常 | 500 | 50000 | 不允许出现在正常用例中 |

> **断言纪律**：任何"应该失败"的用例，必须同时断言 `HTTP status` 与 `code`，并且**不允许出现 500**。参数类异常（`id=abc`）必须 400，项目已用 `_as_int()` 兜底，本轮要做回归。

### 3.3 认证与令牌生命周期

1. 登录返回 `access` + `refresh` + `user`；`user` 不含 password。
2. `refresh` 换新 access，且**轮换 refresh**（旧 refresh 是否立刻失效取决于 `BLACKLIST_AFTER_ROTATION=True`，需实测确认）。
3. `logout` 传 refresh → 该 refresh 进黑名单，再用它 refresh 必须失败。
4. 篡改 token（改一位签名）→ 401。
5. 停用账号后：已签发的 access 在有效期内是否还能用（`InactiveSessionGuardMiddleware` 只挡 Session，JWT 拦截待实测）。

### 3.4 分页边界

| 参数 | 预期 |
|---|---|
| `page_size=1` | 返回 1 条，`total_pages == count` |
| `page_size=100` | 允许（Standard 上限） |
| `page_size=101` | 被截到 100，或 400/参数被忽略——**按实际记录** |
| `page=0` / `page=-1` | 404（DRF 默认 `InvalidPage`）或 400，实测记录 |
| `page=9999` | 404 |
| `page=abc` | 404/400，**不允许 500** |

### 3.5 时间与编码

- 输出时间格式 `YYYY-MM-DD HH:MM:SS`（`DATETIME_FORMAT`）。
- 输入接受 ISO 8601（DRF `DateTimeField`），用例统一用 `%Y-%m-%d %H:%M:%S`，避免格式歧义。
- 中文题干、含引号/换行的解析必须原样回读（JSON 转义正确）。

### 3.6 幂等与并发（P1）

- 重复 `submit`：第二次应返回"已结束"类错误或幂等成功，**不能重复生成作答**。
- 重复 `grade`：`recalc()` 每次重算，分数不叠加。
- 重复 `finalize`：状态不变，不重复出分。
- 并发注册同学号：已知局限（NFR-12），只记录不判缺陷。

## 6. 数据依赖与用例编排顺序

接口之间存在强顺序依赖，**不能按字母序或按文件序执行**。建议按下面的 DAG 编排，前一层失败则后续标记阻塞（不计失败）：

```
[0] 健康检查 → 探活
     ↓
[1] 登录：admin / teacher / os_teacher / studentA / studentB 取 token
     ↓
[2] 班级：建行政班 → 加学生 →（可选）建学科班并绑定教师
     ↓                         （决定教师可见范围、考试开放范围）
[3] 知识点：建根 → 建子（至少 2 层，验证归并）
     ↓
[4] 题目：六种题型各 ≥1 道 → 绑定知识点 →（可选）AI 草稿 → batch 入库
     ↓                         （组卷与统计依赖库存）
[5] 试卷：建卷 → 加题 → 调分/排序 → 发布 → preview/analysis
     ↓
[6] 考试：建考（指定考生与面向全体各一场）→ status=published
     ↓                         （时间窗：now-5min ~ now+30min）
[7] 作答：studentA start → paper → save/answers → heartbeat → behavior → submit
     studentB：开考但不交卷（用于超时/监控/续考用例）
     ↓
[8] 判分：grade（仅客观）→ review（改分）→ grade(with_ai) → finalize
     ↓
[9] 学情 / 推荐 / 监考：report、mastery、trend、practice、proctoring report/evidence
     ↓
[10] 清理：题目/试卷软删除验证（列表消失、历史详情仍在），账号停用（不物理删）
```

**造数原则**（第 5 步落地）：

- 统一前缀：用户名/邮箱/知识点名/试卷名带 `at_<yyyyMMddHHmmss>`，便于识别与清理。
- 账号池：至少 5 个（admin、teacher、os_teacher、studentA、studentB），学生需入班才能被教师"看见"。
- 时间窗：考试 `start_time = now - 5min`、`end_time = now + 30min`，`duration_minutes = 20`，避免写死日期。
- 次数上限：`max_attempts=2`，既够正向又能测"用完"。
- 题目库存：每个题型 × 每个难度至少 1 道，供组卷与统计用例复用。
- AI：默认走降级/mock；需要真实调用的用例单独打标签，串行执行并限次。
