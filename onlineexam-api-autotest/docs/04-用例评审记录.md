## 3. 发现的问题与修订（12 项）

| 编号 | 问题 | 影响 | 修订 |
|---|---|---|---|
| F-01 | ATT-13（切屏强制交卷）与 ATT-15/16（正常交卷）共用 A1，前者会把状态改成已交卷，后者必然失败 | 执行顺序敏感、假失败 | 新增 fixture **E7**（独立强制交卷考试）；ATT-13 改用 E7，A1 只服务正常交卷链路 |
| F-02 | 正文引用了 E5–E8、A5–A10，但 §0.4 fixtures 未定义 | 脚本无法造数 | 补齐 E5/E6/E7/E8、A5/A6/A7/A8/A9/A10 及其用途 |
| F-03 | GRAD-05~08 四种判分策略若共用一份作答，后一次会覆盖前一次分数 | 预期互相矛盾 | 注明"每条独立 attempt，用 `parametrize` 生成"；插入表格时同时修正了 Markdown 断表问题 |
| F-04 | 类型里定义了"场景"，但统计表中场景为 0，口径不一致 | 统计失真 | 改为"场景体现为步骤含 ≥2 接口，类型按主要断言归入功能/一致性/安全"，并同步类型统计 |
| F-05 | 初版漏测 `ai-explain`、`ai-grade`、`ai-notes`、`papers/export`、`grading/queue` | 5 个业务操作无直接用例 | 新增 QUES-31~34、PAPER-33/34、GRAD-29/30 |
| F-06 | 作答列表 `GET /attempts/` 的"教师看全部、学生只看自己"未覆盖 | 重要权限缺口 | 新增 ATT-29 |
| F-07 | 8 条用例预期写成"A 或 B"（如 400 或 404），无法自动判真假 | 脚本只能写宽断言 | 统一标为"允许集合"，执行首轮记录实际值后收敛为单值；收敛结果回填执行记录 |
| F-08 | 计划 215 条、实际 264 条，未解释差异 | 评审无法判断是否失控 | §17 说明三条原因（D-03R 四阶段、文件/AI 类单列、权限拆细） |
| F-09 | P0 占比 59.8%，高于计划的 44% | 回归耗时可能超标 | 保留 P0 分级，但 L0 冒烟只取 33 条；全量 P0 放 nightly，不阻塞每次提交 |
| F-10 | 文件类接口没有 `code` 字段，若按统一断言会必然失败 | 脚本误报 | QUES-26/27、PAPER-33 明确断言 `Content-Type`/文件头，不看信封 |
| F-11 | EXAM-10（迁移到 ongoing）预期不唯一，取决于实现 | 无法判定通过/失败 | 降为 P2，明确"记录实际并回填 D-09 结论"，不作为准出阻塞项 |
| F-12 | 初版未说明 19 个"未单列"操作的处置 | 覆盖率被质疑 | 新增 §20，逐类给出合并理由与执行期抽测计划 |
