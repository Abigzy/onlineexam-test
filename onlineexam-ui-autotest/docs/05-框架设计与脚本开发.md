## 2. 关键设计

### 2.1 等待契约（框架最核心的 30 行）

系统是「服务端骨架 + fetch 注入内容」，所以 `BasePage` 只暴露四类等待，用例里**没有一处 `sleep`**：

| 方法 | 用途 | 反面例子 |
|---|---|---|
| `wait_ready(selector)` | 进页面等业务节点（PO 的 `ready` 常量） | 等 `readyState=complete` |
| `wait_loading_gone()` | 等"加载中…"消失 | 固定 sleep 3s |
| `wait_count(css, n)` | 等列表/卡片数量到位 | `find_elements` 立即取长度 |
| `wait_text(css, 文本)` / `wait_value(css)` | 等结果态（「已保存」/统计卡数值） | 点完就断言 |

### 2.2 登录策略：一条会话两用

- 造数：`ApiSession` 用**表单登录**拿 `sessionid`（页面层与接口层共用 Django session，SessionAuthentication 已开启），非安全方法自动带 `X-CSRFToken` + `Referer`；
- 用例：把同一个 `sessionid` `add_cookie` 注入浏览器，**省掉每条用例 1.6s 的表单登录**；
- 例外：`UI-AUTH-01/02/03` 必须走真实表单（登录本身是被测对象），`UI-AUTH-04` 用**独立会话**——第一轮跑就栽在这：共用会话被退出登录销毁，后面的学生用例全被打回登录页（9 条连锁失败）。

### 2.3 造数与清理：尊重业务规则

造数链路（实测通过）：`random-compose 建卷 → 发布卷 → 建考试（-5min~+3h）→ 发布考试 → 学生可见`。用 **admin 会话**造考试，因为教师建的「面向全体」只覆盖自己可管理班级（FR-6-10），会导致学生看不到。

清理时踩到两条业务规则，已写进代码注释：

| 规则 | 现象 | 框架处理 |
|---|---|---|
| 有作答记录的考试**不可删除** | `DELETE /exams/{id}/` → 400「请改为归档」 | 归档即清理终点（审计要求） |
| 已发布 / 被引用的试卷不能删 | 已发布 → 400；**草稿且被考试引用 → 500（BUG-01）** | 先 draft→delete，失败则保留归档态，并**避免每轮打一条 500 噪声** |

### 2.4 失败现场三件套

`conftest.py` 的 `pytest_runtest_makereport` 钩子：失败时自动挂 **截图 + page_source + 控制台日志 + 当前 URL** 到 Allure。缺陷单里能直接引用，不用再复现一次。

### 2.5 Allure 组织

`epic`=业务域（11 个模块）、`feature`=模块、`story`=用例编号+标题、`severity`：P0→critical / P1→normal / P2→minor。生成静态报告：

```bash
../tools/allure-2.30.0/bin/allure.bat generate report/allure-results -o report/allure-report --clean
```

## 4. 踩过的坑（都已修进框架）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 9 条用例连锁失败，学生全被打回登录页 | `UI-AUTH-04` 退出登录**销毁了共享 sessionid** | 新增 `as_student_isolated` fixture，用独立会话跑退出用例 |
| 2 | 点选项后 `#save-flag` 停在「待保存…」20s | 自动暂存间隔 **30 秒**（`AUTOSAVE_INTERVAL_SECONDS=30`），切题不触发 flush | L0 只断言本地状态；"最终已保存"改 `slow` 用例（40s 超时）。**交卷时会全量兜底提交**，不丢答案（已读 `submit()` 源码确认） |
| 3 | 统计卡断言拿到 `—` | 统计值由 JS 异步填充 | 新增 `wait_value(css)`，等占位符消失 |
| 4 | 班级列表卡片数 0 | 选择器猜错：实际是 `a.class-card`，不是 `.card` | 改 PO 常量（又一次印证"读模板猜选择器命中率约 96%"） |
| 5 | 清理告警刷屏 | 考试/试卷删除受业务规则限制 | 归档取代删除 + 404 幂等处理 + 引用检查 |
| 6 | 题库用例偶发红：`tr` 数 ≥1 但页面仍显示「加载中」 | **假等待**：表格初始 HTML 就有表头和加载行，`wait_count(tr)` 立刻返回 | 改等"真实数据行"信号：题库 `button[data-id]`、试卷 `a[href*='/compose/']`、考试 `tr[data-id]`；`row_count()` 也只数真实行 |
| 7 | 退出登录用例偶发红：URL 无 `next=` | 服务端拦在哪一层不同（mixin 直跳 `/login/` 时不带 next），不是稳定契约 | L0 只断"跳登录 + 页面无业务内容"；`next=` 回跳归 P1 的 UI-SEC-07 |
| 8 | 答题页断言"应有 4 题"却只有 1 题 | **单题模式只渲染当前 1 题**，`.question-block` 数量恒为 1 | 总题数读 `#progress-text` 的 `x/N`；只有全卷模式才数 DOM |
| 9 | 想按题干跳题却找不到（`index_of_stem` = -1） | 同上：单题模式 DOM 里只有 1 道题干 | 先切全卷模式拿全量 DOM 找题号，再用**模式按钮**切回单题（点答题卡格子时若点的是当前题，`gotoQuestion` 会提前 return，既不切换也不重渲染 → OBS-06） |
| 10 | 「继续检查」点不掉弹窗，且不报错 | ① 弹窗 fade 未结束就点，坐标先命中遮罩；② 更关键：**headless 下 CSS 过渡不触发 `transitionend`**，Bootstrap 关闭时卡在"移除 `.show` 但 backdrop 未清、`display` 仍 block"的中间态，遮罩永久拦截后续点击 | ① 驱动启动即注入 `*{transition:none!important;animation:none!important}`；② `Modal.wait_open()` 等 opacity 到 1；③ 弹窗关闭用 **ActionChains 真实指针**（`click_real`）——W3C 的 `element.click()` 不触发 Bootstrap 的 `data-bs-dismiss` 委托 |
| 11 | "上一题点了没反应"（偶发） | 上一条的连锁反应：误触「交卷」后 backdrop 残留，把分页按钮的点击全吃掉 | 分页导航改用 JS 触发（该按钮只挂普通 click 监听，语义等价）；并在切题前做 `ensure_no_modal()` 防御 |
| 12 | 复用造数后 `new_exam` 全部 400「试卷不存在或已归档」 | 上一轮清理把试卷归档了，但 runtime.json 还指向它 | 复用前同时校验 exam 仍 open **且 paper 未归档**；清理结束清空 runtime 的 id，下一轮强制重造 |
| 13 | 结果页断言拿不到逐题徽章 | 未判分的作答不展示逐题对错（成绩可见性规则） | 造数阶段补「判客观题 + 出分」；验"成绩未公开"的考试**只判分不出分**（finalize 等于公开） |

## 5. 如何新增一条用例（团队协作口径）

```python
# scripts/test_l1_auth.py
import allure, pytest
import config
from pages.auth_pages import LoginPage

pytestmark = [pytest.mark.p0]

@allure.feature("01 认证与账号")
class TestLogin:
    @allure.story("UI-AUTH-07 密码错误提示统一文案")
    @allure.severity(allure.severity_level.NORMAL)
    def test_wrong_password(self, anonymous):
        page = LoginPage(anonymous).login(config.ACCOUNTS["student"], "Wrong@123456")
        assert "账号或密码错误" in page.error_text()
        assert "/login/" in anonymous.current_url
```

三条硬要求：
1. **不在用例里写选择器**——新增元素先加到 Page 类的 `L` 字典；
2. **不用 `sleep`**——用 `wait_*`；确实要等（如 30s 自动暂存）就打 `@pytest.mark.slow` 并写清原因；
3. **断言只断可见事实**（文本/数量/可见性/URL），不断言接口报文、不比图表像素；
4. **前端改动后先清缓存再跑**：`OE_FRESH_PROFILE=1 pytest ...`，否则验的是旧 js（见 §4 第 21 条）。
