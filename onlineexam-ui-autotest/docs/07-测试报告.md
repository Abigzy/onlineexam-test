### 1.2 测试分层与判定口径

用例按"改动影响面"分三层，L0 只守"能进得去"，L1 守业务闭环，L2 守边界与异常：

## 4. 覆盖分析

### 4.1 覆盖到什么程度

- **路由**：全站 **35** 条页面路由，自动化覆盖 **26 条业务路由**（PO 层 `pages/*.py` 共定义 27 个 `path`，去掉 `/manage/` 的重复入口后对应 26 条），与步骤 1 定下的范围一致。未覆盖的 9 条以**低适配度页面**为主：`/manage/org/`、`/manage/system/`（AI Provider 诊断按钮会真实外呼）、Django `/admin/`、静态/媒体路由，以及图表看板类页面（只保留"不空白、无 Traceback"级断言，数据口径交给接口层）。
- **主链路**：13 条主链路 **13/13** 有 P0 用例，且每条链路至少 1 条端到端串跑（不是"每页点一下"）。
- **数据一致性**：5 条用例专测"同一份数据在多个视图上是否一致"（卷头统计 ↔ 卷面卡片、成绩列表 ↔ 详情、班级人数 ↔ 成员表…），这类断言最容易假绿，已按 §2 的双视图纪律实现。
- **权限**：12 条用例覆盖三角色越权矩阵，区分 **403** 与 **302→/** 两种拒绝语义（学生/教师访问管理端是 302 回首页，不是 403——按实测口径断言，不按想当然）。

### 4.2 明确没覆盖的（写清楚，避免误解为"已验"）

1. **多浏览器/多分辨率兼容**：只在 Chrome 156 headless 下跑过。Firefox/Safari/Edge 的 CSS 与事件差异未验。
2. **性能与并发**：未做压测。"同时 200 人交卷"这类场景无数据。
3. **文件上传的极端场景**：导入只验了正常 xlsx 与"未选文件"两种；大文件、错列、超长文本、公式注入未验。
4. **AI 能力本身**：AI 出题、AI 批改、AI 学情建议只验了"按钮可用、结果能渲染"，**没有评估生成质量**（这是模型效果问题，不是页面问题）。
5. **安全渗透**：只验了"越权不泄露数据"和"错误页不暴露堆栈/SQL"，未做注入、XSS、CSRF 专项（Django 自带 CSRF 中间件，未单独验证绕过）。
6. **移动端与小程序**：不在本期范围。

## 7. 改进建议

### 7.1 给开发（按优先级）

1. **OBS-11 下拉数据源按权限过滤**：`/classrooms/options/` 应只返回 `can_view` 的班级，与看板权限同源，避免"列表有、点进去 404"。
2. **OBS-12 危险操作确认弹窗带上对象**：把用户名/学号写进标题或正文（`data-username` 已有，只是没用）。
3. **OBS-13 徽章映射按考试状态另建一套**：现在 `STATUS_BADGE` 用作答状态的 key 查考试状态，永远命中灰色兜底。
4. **统一"前端校验 + 后端校验"口径**：BUG-02 的根因是两边不一致——前端要拦、后端也要拦且文案可读（当前后端错误文案是嵌套结构，前端未展平）。

### 7.2 给测试（下一版要做的）

1. **补 CI**（R-3 最优先）：每日 REG、发布前 FULL，红即阻断。先把"数据快照重置"做出来（当前靠 `UIAT_` 前缀隔离，中途 kill 会留脏）。
2. **补兼容性矩阵**：Edge（同内核，先做）+ Firefox（事件模型差异，可能有真问题）。
3. **补性能与并发**：至少做一次"50 人同时交卷"的压测，验证自动暂存与判分队列。
4. **把 3 条 slow 用例纳入周轮**，并给自动暂存加"服务端可配间隔"的开关（现在是 30s 硬编码，测试只能真等）。
5. **用例层继续补"数据一致性"**：当前 5 条偏少，这是最容易出假绿、也最容易出真缺陷的一类。

### 7.3 流程（本项目已验证有效的做法，建议固化）

- **改 PO 必须回跑冒烟 + grep 全仓调用点**：第 4 批删重复类漏改一处，全量才暴露（`AttributeError`），冒烟 1.5min 就能拦住。
- **执行前先 `curl /api/health/`**：本轮两次"红"里有一次是服务被回收（30 条 `ConnectionRefused`），差点被当成 30 个失败用例排查。
- **"跑挂了"要分类**：脚本问题 / 环境问题 / 产品问题，三者处置完全不同。本轮 6 红 2 中断，产品缺陷 0——这个分类纪律让排查没跑偏。
- **缺陷关闭必须过 UI 复验**，并留一条守卫用例常驻全量，"开发说修好了"不作为关闭依据。
