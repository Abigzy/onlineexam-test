## 3. 元素定位策略（本项目的硬规矩）

### 3.1 选择器优先级

| 优先级 | 依据 | 示例 | 为什么 |
|---|---|---|---|
| 1 | `id` | `#question-rows`、`#btn-confirm-submit` | 全站 360 个 id，核心控件基本都有，改版影响最小 |
| 2 | `data-*` | `.q-cell[data-index]`、`.option-row[data-label]`、`button[data-id]` | JS 渲染的行/格用它挂业务标识，比 class 稳 |
| 3 | 稳定语义 class | `.practice-card`、`.stat-card`、`.q-stem` | 只在不绑样式的语义类上用（Bootstrap 工具类不可用） |
| 4 | 容器 + 后代组合 | `#submitModal button`、`#member-list tr` | 缩小范围，避免全页同名冲突 |
| ✗ | 绝对 XPath / nth-child 绑业务 | `//div[3]/div[2]/span` | 加一个广告位就全废 |

**实测结论**：307 条里 **id 类占 68%、`data-*` 类占 12%、语义 class 占 20%**，没有一条依赖绝对路径。

### 3.2 等待契约（这条决定自动化稳不稳）

系统是「服务端骨架 + fetch 注入内容」，`document.readyState=complete` 只代表骨架好了。本项目统一契约：

1. **进入页面**：等 **`wait` 里声明的业务节点**（如 `#question-rows`、`#exam-cards`），最多 20s；
2. **等待内容**：等"加载态消失"——文案 `加载中…` / `spinner-border` 不再出现；
3. **操作后**：等**结果态**（如 `#save-flag` 出现「已保存」、表格行数变化），不是 `sleep`；
4. **禁止**：`time.sleep()` 当同步手段；`readyState` 当判据；`find_elements` 非空当断言。

### 3.3 断言口径

| 场景 | 正确断言 | 错误断言（会假绿） |
|---|---|---|
| 弹窗打开 | `is_displayed()` 为真 且 `#submitModal` 带 `show`/`display:block` | `find_elements('#submitModal')` 非空 —— 它**常驻 DOM** |
| 列表有数据 | `#question-rows tr` 数量 ≥1 且首行文本非"加载中" | 页面 title 正确 |
| 保存成功 | `#save-flag` 文本含「已保存」/ 出现 toast | 点击按钮没抛异常 |
| 权限拒绝 | HTTP 403 或最终 URL 落到 `/`，且**页面无业务数据文本** | 只断言"没报错" |
| 图表渲染 | `canvas` 数量 ≥1 且容器有数据 | 比对图像像素 |

### 3.4 特殊元素的处理约定

| 元素 | 约定 |
|---|---|
| Bootstrap Modal（`#submitModal`/`#examModal`/`#classModal`/`#permModal`/`#addModal`/`#editModal`/`#conflictModal`/`#toggleModal`/`#resetModal`） | 常驻 DOM，**只断言可见性**；关闭后断言 `display:none` 或 `show` 类消失 |
| 答题卡格子 `.q-cell` | 状态看 class：`is-answered` / `is-flagged` / `is-current` |
| 选项 `.option-row` | 选中看 `is-picked`；多选用 `data-multiple="true"` 判断行为 |
| 导出/预览（`window.open`） | `switch_to.window(handles[-1])`，断言 URL 含 `/export/`，**不断言文件内容**；用完 `close()` 回主窗口 |
| 图表（ECharts） | 只断言 `canvas` 存在 + 容器非空；数据口径归接口层 |
| 动态拼接 id（`exam/index.html` 里的 `id="' + item.id + '"`） | **不引用**，改用 `#exam-cards .act-start[data-id]` |

## 5. 排查手册（踩过的坑，按"卡住人的概率"排序）

### 5.1 ⚠ 代理劫持：session 建得出来，但所有命令 `unhandled request`

**现象**：`webdriver.Chrome()` 返回成功，能打印 `browserVersion`；随后 `get()` / `execute_script()` / `set_page_load_timeout()` 全部抛
`WebDriverException: Message: unhandled request`。

**根因**：运行环境注入了 `HTTP_PROXY/HTTPS_PROXY/http_proxy/https_proxy = http://127.0.0.1:63973`。Selenium 客户端把**发给 chromedriver 的 HTTP 命令**也走这个代理，代理不认识 `/session/{id}/url` 这类路径，回 "unhandled request"。

**验证**（排除驱动/浏览器问题）：手工起驱动 + curl 直连，命令全部正常——
```bash
tools/chromedriver.exe --port=9515 &
curl --noproxy '*' -X POST http://127.0.0.1:9515/session -d '{...}'
curl --noproxy '*' http://127.0.0.1:9515/session/<sid>/title      # {"value":""} 正常
```
同样的请求走代理就是 `unhandled request`——问题在链路，不在驱动。

**修法**（写进 `tools/*.py`，步骤 5 也要写进 `common/config.py`）：
```python
import os
for _k in [k for k in os.environ if "proxy" in k.lower()]:
    os.environ.pop(_k, None)
os.environ["NO_PROXY"] = os.environ["no_proxy"] = "127.0.0.1,localhost"
```
**只靠 shell 的 `env -u HTTP_PROXY` 不够**：只要有人漏了某个变量（`ALL_PROXY`、大小写变体）就复现。必须在进程内清，且检查脚本自己也要清（否则 `check_env.py` 自己先挂）。

### 5.2 驱动版本错配：`SessionNotCreatedException ... only supports Chrome version 143`

**根因**：PATH 上有 `chromedriver`（143），Selenium 直接用它；Chrome 已是 156。

**修法**：`Service(r"tools\chromedriver.exe")` 显式指定，并在 `check_env.py` 里做**主版本一致断言**。Chrome 会自动升级（本次实测从 156.0.8078.79 升到 .80），驱动要跟着换。

### 5.3 `DevToolsActivePort file doesn't exist`

**根因**：上一次会话异常退出留下 profile 锁（`--user-data-dir` 被占用）。

**修法**：步骤 5 的 session fixture 里，先用**独立临时目录**或复用固定目录前清理锁；批量跑时不要并发多个 Chrome 用同一个 profile。

### 5.4 服务没起/被回收：`ERR_CONNECTION_REFUSED`

长会话后后台 `runserver` 会被回收。`check_env.py` 的健康检查就是防这个；执行前先跑一次，别让用例替环境背锅。

### 5.5 CDN 慢（9~35s/页）

Bootstrap / Icons / ECharts 全走 `cdn.jsdelivr.net`。固定 `user-data-dir` 命中缓存后降到 0.5s。首次跑或换机器会明显变慢，`page_load_timeout=60` 兜底。

### 5.6 `set_page_load_timeout` 报错的误判

`unhandled request` 出现时容易误判成"这个方法不支持"，其实是 5.1 的代理问题。**先看是不是所有命令都失败**：全失败=链路问题，单条失败=命令问题。

## 6. 实测发现的问题（不是缺陷，但要记录）

### 6.1 演示库已被接口自动化数据占据

`online_exam` 库里现有大量 `at_1103132950_*` 前缀的考试/试卷/班级（接口自动化 229 条跑出来的残留）。影响：

- 列表页第一页几乎全是 `at_` 数据，**用例不能依赖"列表第 1 行"**；
- 步骤 5 造数必须**按关键词/标题精确定位**（如搜 `UIAT_` 前缀），不能按行号；
- 步骤 6 开跑前先跑一次 `UIAT_` 残留清理。

### 6.2 教师账号当前没有任何「可管理班级」

`teacher` 的 `classrooms` 关系为空 → 访问 `/classrooms/32/` 的 API 返回 403（页面壳仍渲染）。处置：

- `teacher-classroom-detail` 的定位器实测改用 `admin` 会话（管理员可管理全部班级）；
- 班级增删改用例（UI-CLS-05/07）留到步骤 6 用 `UIAT_TEA` 自建班复测。

### 6.3 三处「内容为空」是权限作用域，不是缺陷

| 页面 | 控制台报错 | 判定 |
|---|---|---|
| `/exams/34/take/` | `GET /api/v1/exams/34/start/` 404 | 该生对 exam 34 已有 graded 作答，不能再开考 → 页面走错误态。**正常作答态需造新考试** |
| `/question-bank/2419/edit/` | `GET /api/v1/questions/2419/` 404 | 题目不在该教师的学科作用域内 → 按"跨人 404"纪律拒绝，**不是缺陷** |
| `/exams/466/monitor/` | `GET /api/v1/exams/466/attempts/` 404 | exam 466 由其他账号创建，教师看不到 → 符合 FR-6-10 收窄规则 |

**结论**：这三条 404 都符合设计（跨人/越权一律 404），**不得当缺陷上报**。副作用是这几页的"有数据态"没被实测覆盖，已列入步骤 6 的复测清单。

### 6.4 定位器初版猜错了 5 处（实测纠正）

| 页面 | 错误假设 | 实际 DOM |
|---|---|---|
| 学生/教师首页 | `.stat-chip` / `.feature-card` | 登录态是 `.stat-card` + `.stat-value`；`.stat-chip`/`.feature-card` 只在**未登录落地页** |
| 考试列表 | `#pager` | 没有该 id，是 `#page-info` + `#btn-prev/#btn-next` |
| 管理看板 | `.card` | 没有，是 `.page-head` + `.stat-card`（16 组） |
| 学生班级详情 | `#btn-add` / `#addModal` | 学生只读，这两个元素**根本不存在**（不存在才是对的） |
| 题型筛选等 | — | 与模板 id 一致，一次通过 |

这件事本身说明一个道理：**定位器必须实测，读模板猜出来的命中率约 96%**——剩下 4% 就是上线后半夜报警的根源。

### 7.2 必须写进框架的 6 条约束

1. **进程内清代理**（§5.1），放 `common/config.py` 顶部，import 即生效；
2. **驱动路径与版本自检**（`tools/chromedriver.exe` + 主版本比对），启动前失败就 abort，不要降级重试；
3. **等待契约**（§3.2）封装成 `BasePage.wait_ready(selector)` / `wait_text(selector, text)` / `wait_count(selector, n)` / `wait_loading_gone()`；
4. **失败三件套**：截图 + `page_source` + 控制台日志（`goog:loggingPrefs`），挂 Allure；
5. **会话复用**：登录用 `requests` 表单取 `sessionid` 注入 cookie（省 1.6s/条），但 `UI-AUTH-01/02/03` 必须走真实表单；
6. **数据定位**：一律按标题/关键词定位（`UIAT_` 前缀），禁止"列表第一行"。

### 7.3 Allure 落地方式

```bash
# 生成原始结果
python -m pytest --alluredir=report/allure-results
# 生成静态报告（一条命令搞定：generate + 入口重命名为 uireport.html）
bash tools/gen_report.sh
# Windows / PyCharm 里没有 bash 时用 Python 版，效果完全相同
python tools/gen_report.py
# 等价手工版：allure generate ... --clean 之后把 index.html 改名为 uireport.html
```
分类建议：`epic`=业务域、`feature`=模块、`story`=用例标题、`severity`=P0/P1/P2、附件=三件套。

> **每次跑完测试都要执行上面这条生成命令**，不是"要交报告时才跑"。`pytest.ini` 的 `--clean-alluredir`
> 会在每次启动时清空 `report/allure-results`，不重新生成的话，报告目录里留着的是上一轮结果。
>
> **这一步已经默认替你做了**：`config.AUTO_REPORT` 默认开启，pytest 会话收尾会自动执行同一套
> 生成流程，输出末尾多一行 `[auto-report] 154 条 / 6.3s -> …/uireport.html`。它调的是
> `common/report_builder.py`，与 `tools/gen_report.py` 是同一份代码，不是两套实现。
> 所以 `pytest` 一条命令就够，上面那条手工命令只在**自动生成失败时兜底**（失败只打一行警告、
> 不改退出码，此时按提示手工重跑）。只想跑用例不要报告，用 `OE_AUTO_REPORT=0 pytest -q`。
