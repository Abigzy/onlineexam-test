## 1. 背景与目标

### 1.1 背景

1. 系统 11 个业务模块已完成，页面 35 条路由 / 31 个模板，三角色分流。
2. 功能测试已完成 246 条用例、7 个缺陷闭环（`onlineexam-fun-test`），但**全部依赖人工执行**，每次提测重跑成本约 1.5 人日。
3. 接口自动化已完成 229 条（`onlineexam-api-autotest`），**只覆盖接口层**，无法证明"点了按钮页面会变"。
4. UI 走查 251 个检查点（`docs/UI走查清单.md`）只证明"页面能打开、能渲染、不溢出"，**不点按钮**。
5. **缺口**：没有任何自动化守"交互 → 状态变化"这条链路。判分改分后成绩单有没有变、教师建完考试学生能不能看到、题库停用后列表状态对不对——这些今天只能靠人眼。

### 1.2 目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G-1 | 三角色核心主链路可一键回归 | L0+L1 共 102 条 ≤ 22 min 跑完 |
| G-2 | 跨页面状态流转被钉死 | §3.2 的 13 条主链路，每条至少 2 个跨页面断言 |
| G-3 | 权限的**显示层**被守住 | 越权页、导航入口可见性、按钮级权限共 ≥10 条断言 |
| G-4 | 测试结果可重复 | 全量连跑两轮 0 diff；同一用例 3 次执行结果一致 |
| G-5 | 产出可复用资产 | PO 页面类 + 组件封装 + 造数工厂 + 报告模板，下个版本直接加用例 |

### 1.3 非目标

- 不以"发现缺陷数量"为 KPI，本轮以**建立可回归基线**为首要目的；
- 不替代功能测试的探索性验证，不替代接口层的规则校验；
- 不做代码修复（发现缺陷只给定位线索与证据）。

## 3. 测试策略与类型

### 3.1 分层策略（决定"哪些先做、哪些可砍"）

| 层 | 定位 | 用例数 | 触发时机 | 时长目标 | 失败含义 |
|---|---|---|---|---|---|
| **L0 冒烟** | 三角色能登录、9 个核心页能打开且不空白 | 15 | 每次代码提交 / 每日 | ≤ 3 min | 环境或主流程断裂，**阻断提测** |
| **L1 主链路** | 13 条业务链路端到端状态流转（含 13 条 P0 非冒烟用例） | 87 | 每次提测 / 每日 | ≤ 18 min | 业务功能回退，**阻断上线** |
| **L2 交互与边界** | 表单校验、空态、弹窗取消、页签、分页、权限可见性 | 48 | 版本级 / 周级 | ≤ 14 min | 体验与边界问题，可带风险上线 |

> 分层与优先级是**两个维度**（步骤 3 定稿口径）：15 条 P0 打了冒烟标记进 L0，其余 13 条 P0 与 74 条 P1 同属 L1，48 条 P2 即 L2。

**取舍原则**：环境不稳时先保 L0；时间不足时砍 L2，不砍 L0/L1。

### 3.2 13 条主链路（L1 的骨架，来自步骤 1 §4）

| 编号 | 链路 | 覆盖层 |
|---|---|---|
| S-1 | 注册 → 登录 → 首页角色分流 | L1 |
| S-2 | 我的考试 → 开考 → 作答 → 交卷 → 结果页 | L1（**最高优先级**） |
| S-3 | 答题页刷新不换题（断网续考） | L1 |
| S-4 | 错题本 → 我的学情 → 每日练习提交 | L1 |
| S-5 | 班级可见性（本班有名单 / 非本班权限弹窗） | L1 |
| T-1 | 题库新增 → 列表可见 → 编辑回填 → 停用 | L1 |
| T-2 | 题库导入（模板下载 + 导入结果明细） | L1 |
| T-3 | 组卷：勾知识点 → 试算 → 生成 → 列表可见 | L1 |
| T-4 | 教师建考试 → 学生端可见（**双会话联动**） | L1（重点） |
| T-5 | 判分队列 → 改分 → 定稿 → 成绩单变化 | L1 |
| T-6 | 作弊看板 → 证据链三段内容 | L1 |
| A-1 | 管理员建号 → 新号可登录且角色正确 | L1 |
| A-2 | 管理员代管教学功能（黄条 + 返回控制台） | L1 |

### 3.3 测试类型矩阵

| 类型 | 做什么 | 归属层 | 断言方式 |
|---|---|---|---|
| 功能交互 | 点击/输入/提交后的页面变化 | L1/L2 | 可见 DOM + 文案 |
| 表单校验 | 必填、格式、长度、非法值的前端提示 | L2 | 错误文案出现 + 不跳转 |
| 状态流转 | 订单/考试/批改等对象状态标签变化 | L1 | 状态标签文本 |
| 权限可见性 | 越权 URL 的 403/跳转、导航入口不出现、按钮级控制 | L2 | 状态/落地页/元素缺失 |
| 数据展示一致性 | 页面显示与接口返回/DB 记录一致（抽样） | L1 | 页面文本 vs 接口值（**只读比对**，不断言接口契约） |
| 空态与错误态 | 无数据、接口失败时的可读提示，不暴露 Traceback | L2 | 文案包含匹配 |
| 兼容性 | Chrome 156 × 1440×900 / 1280×800 两视口 | L2 | 元素可见、无遮挡 |
| 回归 | 缺陷修复后针对性 + 核心链路 | L1 | 同上 |

### 3.4 设计方法（步骤 3 执行）

等价类（输入域）→ 边界值（分页首末页、题量 0/1/最大、密码长度）→ 判定表（角色 × 状态 × 操作）→ 场景法（13 条主链路的基本流/备选流/异常流）→ 状态迁移（考试 attempt：未开考→进行中→已交卷→已批改→已出分）。

### 4.2 数据策略

**原则：接口造数，UI 只读写页面；造数带前缀，用后精确清理。**

| 数据 | 数量 | 造法 | 生命周期 |
|---|---|---|---|
| UIAT 学生 / 教师 | 各 2 | `POST /auth/register/`（学生）、管理员建号（教师） | 会话级，结束删除 |
| 知识点 + 六题型题目 | 1 树 + 6 题 | `POST /knowledge-points/`、`POST /questions/` | 用例级 |
| 试卷 | 2（纯客观 / 含主观） | `POST /papers/` + `random-compose` | 用例级 |
| 考试 | 3（进行中 / 已结束 / 未开始） | `POST /exams/`，**时间窗写 +3h** | 用例级 |
| 作答与成绩 | 2（待批改 / 已批改） | `POST /attempts/{id}/save/` + `finalize` | 用例级 |
| 班级 | 2（本班 / 他班） | `POST /classrooms/` | 用例级 |
| 导入夹具 | 1 个 `.xlsx` | 仓库固定文件 `data/import_sample.xlsx` | 长期 |

- 造数结果写 `data/runtime.json`（ID 清单），清理阶段按清单精确 DELETE；
- **失败用例的数据不删**，留作定位现场，由下一次全量执行前的清理步骤统一收；
- 不使用"列表第 1 行"这类弱定位，避免数据顺序变化带来的假失败。

### 4.3 元素定位策略（步骤 4 细化，这里定原则）

1. 优先级：`id` > `data-*` > 稳定语义 class > 文案 > **禁用**绝对 XPath；
2. 定位器**集中**在 Page 类常量区，页面改版只需改一处；
3. Modal 常驻 DOM，一律断言可见性（`is_displayed()` / `.show`），不断言存在性；
4. JS 注入内容必须等"业务节点出现 + 加载态消失"，`readyState=complete` 不作判据；
5. 动态 id（如 `id="' + item.id + '"` 形式）一律不引用，改用 `class + data-*`；
6. 文案断言用"包含匹配"+ 常量，避免改标点就红。

## 7. 进入与准出标准

### 7.1 进入标准（提测准入）

全部满足才开跑：

1. `GET /api/health/` 返回 200，服务用 `--noreload` 启动；
2. 演示账号 admin / teacher / student 均能登录；
3. 演示数据齐备：≥1 份可用试卷、≥1 场可开考的考试、≥1 条已批改作答、≥2 个班级（本班/他班）；
4. 驱动版本自检通过（Chrome 主版本 == chromedriver 主版本），否则直接判"环境不满足"；
5. 造数脚本可独立跑通，`data/runtime.json` 能生成；
6. 元素定位清单已评审（步骤 4 交付）。

### 7.2 准出标准（发布门槛）

1. **P0 执行率 100% 且通过率 100%**；
2. P1 执行率 100%，通过率 ≥ 95%；
3. **致命 / 严重缺陷 0 条遗留**；一般缺陷遗留需有明确影响面说明与规避方案；
4. 全量**连跑两轮结果一致**（同一批用例通过/失败集合相同）；
5. Allure 报告完整：每条失败用例附截图 + 页面源码 + 控制台日志；
6. 遗留数据已清理，演示库回到基线（52 用户 / 701 题 / 8 试卷 / 20 考试，允许 `UIAT_` 造数残留 0 条）；
7. 测试报告给出**明确结论**：可上线 / 带风险上线 / 不建议上线。

### 7.3 暂停与恢复标准

出现下列情况**停止执行**，记录断点后转缺陷跟踪：

| 情况 | 处理 |
|---|---|
| 服务不可用或 5xx 连续 > 3 次 | 暂停，通知开发，30 min 内不可恢复则当日终止 |
| 登录/开考/交卷任一主流程阻塞 | 暂停全量，先修阻塞项 |
| 演示库数据被破坏且无法回滚 | 暂停，重建演示数据后从头跑 |
| 浏览器/驱动升级导致批量失败 | 暂停，锁定版本后复跑 |

## 9. 执行与监控方式

| 项 | 做法 |
|---|---|
| 执行入口 | `pytest -m smoke`（L0）/ `pytest -m "p0 or p1"`（回归）/ `pytest`（全量） |
| 并发 | **串行**（`-p no:randomly`），不做 xdist 并行（账号与考试态会互串） |
| 失败现场 | 自动截图 + 保存 `page_source` + 浏览器控制台日志 + 当前 URL，全部挂到 Allure |
| 日志 | 控制台 + `log/ui_YYYYMMDD_HHMMSS.log`，记录用例名、步骤、定位器、耗时 |
| 报告 | Allure：epic=业务域 / feature=模块 / story=用例标题 / severity=P0-P2 / 附件=三件套 |
| 监控指标 | 通过率、执行时长、稳定性（两轮 diff 数）、定位器失效率（因定位失败 vs 断言失败的比例） |
| 回归节奏 | 提交级跑 L0；提测级跑 L0+L1；版本级跑全量并归档报告 |
