## 1. 编号与字段约定

**编号规则**：`UI-<模块缩写>-<序号>`，缩写与模块一一对应：

| 缩写 | 模块 | 条数 | 缩写 | 模块 | 条数 |
|---|---|---|---|---|---|
| `UI-AUTH` | 01 认证与账号 | 18 | `UI-EXAM` | 02 学生·考试闭环 | 24 |
| `UI-STU` | 03 学生·学情练习 | 14 | `UI-CLS` | 04 学生·班级 | 7 |

| `UI-ANA` | 09 教师·学情与作弊 | 8 | `UI-ADM` | 10 管理端 | 8 |
| `UI-SEC` | 11 权限与可见性 | 10 |  |  |  |

**优先级口径**（沿用测试计划 §7.2 的准出标准）：

| 优先级 | 含义 | 执行时机 | 失败后果 |
|---|---|---|---|
| P0 | 主链路的「能通」与角色分流；15 条另打 `smoke` 标记进 L0 | 每次提交 | 阻断提测 |
| P1 | 主链路的细节正确性、数据一致性、跨页面状态流转 | 每次提测 | 阻断上线 |
| P2 | 边界、空态、校验文案、兼容性 | 版本级 | 可带风险上线 |

**用例类型**：功能 / 交互 / 校验 / 权限 / 数据一致性 / 异常 / 兼容性。

**步骤写法**：`#id` 表示元素 id 定位器，`.class` 表示 class 定位器，
`[data-xxx]` 表示属性定位器——这些都是步骤 4 要落进 PO 常量区的真实定位依据，不是示意。

## 7. 评审要点（步骤 3 的 Gate G1）

1. **条数与分布**：150 条、P0 28 / P1 74 / P2 48、冒烟 15，与计划 §5 逐模块一致（生成器已断言）。
2. **可执行性**：每条步骤都落到具体 URL 与定位器；无「验证功能正常」这类不可执行描述。
3. **可判定性**：每条预期都是可观察事实（数量、class、文案、URL、可见性），无「界面友好」类主观表述。
4. **去重**：与接口自动化、UI 走查、单测的重叠已在 §2.3 逐项剔除。
5. **数据安全**：所有造数带 `UIAT_` 前缀，依赖清单与清理方式齐备（§4）。
